## isa.md 的改动记录

**v2.24（2026-09-27）——操作码整体后移一位，`0000` 空出来当空操作（§3、§4、§8、§10）；译码器接线不变，全部机器码全部重编。**

- **§3 opcode 表新增 `0000 保留（空操作）` 行**，其余十一条一律 +1：ALU 寄存器型 `0001`、立即数型 `0010`、`LDA 0011`、`STA 0100`、`LD 0101`、`ST 0110`、`BZ 0111`、`BNZ 1000`、`JMP 1001`、`OUT 1010`、`HLT 1011`。保留码区由 `1011-1111` 收窄成 `1100-1111`。§3 的 `X` 字段那段与 §5 里点名 `op` 值的句子、§4 的编码示例、§9 的编码公式同步改数。
- **动机写进 §10**：`op=0000` 那根译码线一根门都不接，全 0 的指令字译出的控制位全 0——不写寄存器堆、不写 RAM、不写 C。复位后的 `IF/ID` 是全 0（Logisim 寄存器只有异步清零），分支 flush 要灌的也是全 0，两者都必须是空操作而不是 `ADD R0,R0,R0`。
- **§8 控制信号的 `op` 编号同步**：`RegWrite = op1|op2|op3|op5`、`MemRead = op3|op5`、`MemWrite = op4|op6`、`BSrc = op2|op3|op4`、`BranchZ = op7`、`BranchNZ = op8`、`Jump = op9`、`OutEn = op10`、`Halt = op11`、`CWrite = (op1|op2) && !fn[3] && !fn[2]`。或门个数与判据形式都没动，变的只是各门的输入取自哪根线。

**v2.23（2026-09-27）——§8 `MemWrite` 行的接线说法改正为 `MemWrite && ClockEnable`；编码、控制信号与全部机器码一字未动。**

- **§8 `MemWrite` 行**：原句"直接接 RAM 的写使能脚"与 `docs/datapath.md` §1 / §2.5 不一致——`datapath.md` v2.21 给数据 RAM 的写加进全局停机使能（`MemWrite && ClockEnable`）后，这一句没跟着改。改为写明要与 `ClockEnable` 相与。

**v2.22（2026-09-26）——`MemToReg` 并入 `MemRead`，控制信号由 12 个减为 11 个（§7、§8）；编码与全部机器码一字未动。**

- **§8 的两行合并成一行 `MemRead`**：两个信号恒等（只有 `LDA` / `LD` 为 1），译码器里本来就是一个 `op2|op4` 或门。合并后这一个名字承担三处用途——ID 段的停顿判据、EX 段前递优先级 1 的排除项、WB 段写回 mux 的选择端（见 `docs/datapath.md` v2.26）。
- **§8 逐条指令表删掉 `MemToReg` 一列**，转置表里 `LDA` / `LD` 两行同步删词；§7 的 WB 行随之改写成"写回 mux 按 `MemRead` 选择写回值"。
- **§8 末段"两个名字是因为取用的位置不同"整段改写**。合并的边界是"读 RAM 这一态内部不再分线"，不是"访存只用一根线"——读 / 写 / 都不是仍是三态，`MemRead` 与 `MemWrite` 两根都要（`MemWrite` 是 RAM 的真引脚，`MemRead` 不接 RAM，两者本来就不对称）。

**v2.21（2026-09-25）——§8 把前递优先级 1 的排除项改记在 `MemToReg` 名下；编码、控制信号与全部机器码一字未动。**

- **§8 `MemRead` 行的用途收窄**：原文写它是"给 load-use 停顿和前递优先级 1 的排除项用的标志"。前递那一项改用 `MemToReg`（见 `docs/datapath.md` v2.23），这一行只剩停顿。
- **§8 `MemToReg` 行补前递用途**：写明前递单元也读这一位——`EX/MEM` 里装着 load 时它的写回值还没出来，优先级 1 因此带 `!EX/MEM.MemToReg`。
- **§8 末段"两个名字是因为消费的级不同"改写**：原文只说 `MemRead` 在停顿与前递排除里用、`MemToReg` 锁存到 `MEM/WB`；现在两个名字的分工是"停顿用 `MemRead`、写回 mux 与 `EX/MEM` 上的前递排除用 `MemToReg`"。

**v2.20（2026-09-22）——§9 的 `HLT` 段不再另列冻结清单；编码、控制信号与全部机器码一字未动。**

- **§9 的 `HLT` 段**：原句"冻结全部时序元件（PC、四级流水线寄存器、C 标志、Output 寄存器）"里的清单不全（漏了寄存器堆与数据 RAM 的写），与它自己声称的"全部"矛盾。改为只留结论，清单指向 `docs/datapath.md` §1——接线以那份为准，两份各列一份必然走岔。

**v2.19（2026-09-22）——同步 `datapath.md` v2.18「分支判定挪到 EX 段」：§7 的 ID / EX 两行、§4「表里没有的东西」里两处对分支网络的描述、§9 整节；编码、控制信号与全部机器码一字未动。**

- **§7 各段职责**：ID 段不再出现"判零"，改为译出 `BranchZ`/`BranchNZ`/`Jump` 并做停顿检测；EX 段补上"`BZ`/`BNZ` 判零、`JMP` 决定跳转，驱动 flush 与 PC 目标 mux"。表下那段"ID 段的全部取用方"里的"`BZ`/`BNZ` 判零"换成"停顿检测"。
- **§4「表里没有的东西」里两处连带**：加间接跳转那条约的"要把分支那套 ID 段前递加停顿照搬一份"不再成立——源就在 `rs1` 槽、前递与停顿本来就逐字段盲比两个源槽，要加的只是把取值口换到 `A_mux_out` 之后；加比较并分支那条约的"要把取值与停顿条件从只比 `[11:8]` 扩成两个源都比"同样不再成立，只剩一个相等比较器的钱。
- **§9 整节改写**：一句话判据由"两类指令（EX 段用 / ID 段用）"塌成一类；漏网清单由四类塌成一类（只剩 k=3），分支归入普通规则、不再另算；比较网络对照表由三套减到两套；`&& !stall` 那句随之删除。

**v2.18（2026-09-22）——§4 的 `CMP` 那条里「代价那一侧反而要付」这句挪回它该在的位置；编码、控制信号与全部机器码一字未动。**

- **v2.9 把「真机取代 `CMP` 的是比较并分支」插在了这句之前**，于是"代价那一侧反而要付：新开 opcode 并给 `RegWrite` 加恒 0 特例，或拿一个真实寄存器当垃圾槽"读起来像是在说比较并分支。它是 `CMP` 的代价——比较并分支一个寄存器都不写，两样都不需要。挪到 `CMP` 与 `SUB` 的比较之后，并把"省下的只有不写回这个动作、而这里没地方写"这层因果写明。

**v2.9（2026-09-22）——§4 的 `CMP` 那条补上「真机为什么留它」的机理与真机真正的替代品；编码、控制信号与全部机器码一字未动。**

- **v2.8 那句「`CMP` 只是"`SUB` 但不写回"」没说到点子上**：真机上 `CMP` 值得留靠的不是算差值这个动作，而是它有地方可写——它写的是标志寄存器，条件分支直接读标志、不读通用寄存器。补上这条机理带来的三件事（`SUB Rd,...` 得先有空着的 `Rd`、一次比较能被后面多条条件分支接着用、结果不挤通用寄存器写口），并点明本 ISA 没有标志寄存器这一路（`C` 是除寄存器堆、RAM、PC 之外唯一的架构状态位），`BZ` / `BNZ` 判的就是通用寄存器，所以在这儿 `CMP` 与 `SUB` 确实没有区别——v2.8 的结论不变，变的是理由。
- **顺带点明真机取代 `CMP` 的其实不是 `SUB`，而是比较并分支**（MIPS / RISC-V / ARM64 的 `BEQ Rs1,Rs2,label`）。本 ISA 的缺口是「分支只会判零、连两值相等都判不了」，不是缺 `CMP`；要加就加这个。同时记下它的成本：编码放得下（`Rs2` 正好占分支空着的 `rd` 槽），要花的是把分支的取值与停顿条件从只比 `[11:8]` 扩成两个源都比。

**v2.8（2026-09-22）——§4「表里没有的东西」补 `CMP`；编码、控制信号与全部机器码一字未动。**

- **§4「表里没有的东西」原先没有 `CMP`**：那节的否定清单列了 `CALL` / `RET`、`PUSH` / `POP`、`NOT`、移位、乘除、间接跳转六类，`CMP` 不在其中；全仓库（`isa.md` / `datapath.md` / `CHANGELOG.md` / `README.md` / `asm/`）搜 `CMP` 零命中，它从来没被讨论过。补进清单，并加一条说明。
- **说明的落点**：`CMP` 被 `SUB` 覆盖——`SUB Rd,Rs1,Rs2` 一条指令同时给出差值与 C，紧跟 `BZ Rd,eq` 判的就是相等，`CMP` 只是"`SUB` 但不写回"，指令数一模一样；真机里它的价值大半在按 C 走的条件分支（`BGT` / `BLT` 那一族）上，而本 ISA 的分支只有 `BZ` / `BNZ`、都只判零，所以它换不来新表达力；代价那一侧反而要付（新开 opcode 并给 `RegWrite` 加恒 0 特例，或占一个真实寄存器当垃圾槽）。顺带点明判大小要先把 C 搬进寄存器（`LDI R0,0` 紧跟 `ADC R0,R0,R0`）再 `BZ`。
- **这与 §5 末「为什么不加 `NOT`」是同一种答复**（省不下东西，不是没位置），故只在 §4 写一处，§5 不动。

**v2.7（2026-09-21）——§6 补「助记符大小写不敏感」。编码、控制信号与全部机器码一字未动。**

- **§6 原先只承诺了寄存器名大小写不敏感**（`r1` 等同 `R1`），但汇编器对助记符也做了 `upper()`，`add r1, r2, r3` 一直能汇编。补上这一条，免得读者以为助记符必须大写。

**v2.6（2026-09-21）——采纳 v2.5 记下的那条路：两条 store 的数据源移进自己空着的源槽，`[15:12]` 从此只写不读。`ST`/`STA` 的机器码全变，指令语义与全部判据值一字未动；`datapath.md` 同步为 v2.8。**

- **编码表两条 store 换布局**：`STA Rs,addr` 的数据源由 `[15:12]` 移到 `[11:8]`，`ST Rs,[Rs1]` 的移到 `[7:4]`，两条的 `[15:12]` 恒编 0；助记符里那个具名寄存器随之由 `Rd` 改称 `Rs`（它是**源**）。§4 的编码公式、位模式实例（新增 `ST`/`STA` 两条）、§6 的操作数顺序说明、§8 的两张控制表同步。
- **§4 那一小节整体重写**：原「为什么 store 的数据寄存器占的是 `rd` 槽」按"备选、未采用"写成，现改为「目标恒在 `[15:12]`，两条 store 的数据源各占自己的源槽」——目标之所以钉死在那格，是因为写口地址硬接线到 `[15:12]` 的锁存副本（没有 `RegDst` mux），能挑位置的只有 store 的源。原先论证"共享是被 opcode 预算逼出来的"那一段保留（它现在证明的是"数据源必须借用源槽"），三读口占用表换成两读口，删去"`[15:12]` 买到的主要是读起来顺"与"不采用那条路的代价"两段（那条路已是现行设计）。
- **§4「操作数在哪个槽」由三读口改两读口**：删掉 C 口一列，`STA`/`ST` 的写数据分别落在 A 口 / B 口，"四条访存指令 `Rd` 含义一致"那句改成"写目标恒在 `[15:12]`、源只在两个源槽里"。
- **§9 的三套网络对照表**：A/B/W **三个**前递 mux 改为 A/B **两个**，`dep` 的比较字段由三个减到两个。
- **`fn` 表 / `PASS` 表 / §8 实现说明里的 store 说明**按新通路改写：`STA` 的写数据经 A 前递 mux、`ST` 的经 B 前递 mux（§8）；`PASS` 对照表加一行对照项，说明 `STA` 的数据源虽然也在 A 口上，但它不经过 ALU。
- **「字段没有重叠」补一句**：没有任何一条指令既带 `rs2` 又带立即数，所以"源"与"立即数位"两种身份在同一格里永不共存（逐字段盲比仍会拿立即数位去比，那只造成多停，见 `datapath.md` §5.2）。
- **§4「目标恒在 `[15:12]`」那节补上"这条性质为什么值钱"**：原先只列了三处收益（读口 2 个 / `dep` 2 个比较器 / 写数据不必自带前递 mux），没点破它们共同的来源是"读口与比较网络都硬接线 ⇒ 某一格可能装源就等于要为它常驻配一套读 + 比"，读者容易把"源放哪一格"当成纯记法问题。同时点明**吃这份差价的只有数据通路，译码器不涉及**（控制信号只由 `op`/`fn` 生成）。

**v2.5（2026-09-21）——§4 补「两条 store 各用自己的空格子」这条路的完整账；编码表、指令语义与全部机器码一字未动。**

- **§4「借用现成的空格子」那一段原先不完整**：它只答了"两条 store 的空格不是同一格 ⇒ 交集只有 `[15:12]`"和"强行统一到 `[11:8]` 会连累 `ST` 的地址寄存器"两种排法，**没答"那就各用各的格子"**——而那两格各自正对一个硬接线的读口，读得到。补上：写数据通路加一个 `(MemWrite ∧ BSrc) ? A_mux_out : B_mux_out` 的二选一即可（`BSrc` 对 `STA` 恒 1、对 `ST` 恒 0，用现成控制位选，不新增流水线字段），前递的比较字段仍是固定位段；收益是 `[15:12]` 从此不当源 ⇒ `dep` 少一个比较器、**读口可以从 3 个减到 2 个**（连 `ReadDataC` 与 W 前递 mux 一起省掉）。**并写明 `[15:12]` 这个"统一"买到的是"读起来顺"（不是正确性、也不是速度），不采用那条路的理由是"重编 + 判据体系重做"的代价远大于几个便宜元件，不是硬件上做不到。**

**v2.4（2026-09-20）——§4 补「为什么 store 的数据寄存器占的是 `rd` 槽」、§9 改正「比较一律取裸字段」的说法、全文把角色名「生产者/消费者」换成「写 Rd 的那条 / 读 Rd 的那条」；编码表、指令语义与全部机器码一字未动。**

- **§4 在「字段为什么这样排」之后新增一小节**：读者看懂了流水线之后反过来会问"既然 `ST`/`STA` 的 `rd` 槽装的是源，为什么不挪个格子"。补上完整论证：ALU 立即数型整满 24 位 ⇒ `rs2` 与"必须参与比较的角色"里至少一个要住进立即数字节 ⇒ **比较字段与立即数位重叠是这个 ISA 的固有性质**（不是接线疏忽）；要给 store 数据单独开一格需要字节外三个互斥半字节，连扁平 opcode 也只剩 4 位（16 个），装不下 18 条助记符 ⇒ **共享是被 opcode 预算逼出来的**；并说明换排法只是把重叠挪到地址寄存器头上。现状胜出在三条：`[15:12]` 是唯一每个 opcode 都是寄存器号的字段、`ID/EX.rd` 一物两用省一个 4 位流水线字段、被重叠的 `[7:4]` 只对一个指令类是真源。
- **同节钉死一处易记错的事实**：**`STA` 没有地址寄存器**——它的地址就是立即数 `addr[7:0]`，只有 `ST` 才是"地址寄存器 + 数据寄存器"。
- **同节补「借用现成空格子」这一路的答复**：原文只论证了"**单独开一格**要付 4 位 opcode 的代价"，没答"**ST / STA 本来就有空格子**，为什么不用"。补一张三读口占用表：`ST` 空的是 `[7:4]`、`STA` 空的是 `[11:8]`，两条 store 的空格**不是同一格**，硬接线（无读口地址 mux）下交集只有 `[15:12]`；而它之所以在两条 store 里都空着，正因为它是目标寄存器槽、store 不写寄存器。
- **同节补 `rs2` 取高半字节的依据**：假命中的条件是写 Rd 的那条的 `rd` 等于这一格所代表的立即数半字节，半字节取值越集中、能撞上的目的寄存器越少。给出 `examples/` 的实测分布（49 个 8 位立即数/地址操作数：高半字节 5 种取值、低半字节 11 种）。
- **§9 改正一处与 §4 自相矛盾的说法**：原文写"所有比较用的寄存器编号都取**裸字段** `Inst[11:8]` / `[7:4]` / `[15:12]`"。这对 ID 段那两套网络（`dep`、分支操作数 mux）成立，对 **EX 段那三个 A/B/W 前递 mux 不成立**——它们比的是 `ID/EX.rsA` / `rsB` / `rd`，即同样三个位段的**锁存副本**，因为读 Rd 的那条进 EX 时 `IF/ID` 早已换成后面第四条指令（`datapath.md` §2.7）。补一张三套网络的对照表，并点明分界是"读 Rd 的那条此刻在哪一段"、这两组线别接混。
- **§9 判据句"在 EX 段用"的名单改正两处**：原文列"ALU 族/LD/ST/STA/OUT"，① 把**漏掉的 ALU 立即数型**补回来——`ADD R1,R2,#5` 读 `rs1`，确实在 EX 段用；② 例外从只写 `LDA` 改成 **`LDI`/`LDA`** 两条——`LDI` 同样是 `BSrc=1` → `PASS.B`、A 口那份读数不参与运算，也一个寄存器都不读。名单与 `datapath.md` §4.2 表首行、`CLAUDE.md` 冒险表首行**三处同步**（原先三处措辞各不相同：一处"ALU 族"、两处"R 型"）。

1. **指令位宽 16 → 24 位**，字段改成半字节对齐的 `op(4) fn(4) rd(4) rs1(4) X(8)`。原先"立即数拆进 `[8:6]`/`[5:3]`/`[2:0]`"的**位重叠消失**——那是 v1 唯一一处"读错了电路照样跑对"的地方，本版没有了。
2. **寄存器 8 → 16 个**，`rd`/`rs1`/`rs2` 各占满一个半字节。
3. **R0 不再是恒零寄存器**，16 个全部通用可读写；汇编器不再禁止 `Rd=R0`。v1 §2 "读出恒 0 不是装饰"那段随之作废。
4. **新增立即数运算型**（`ADD Rd,Rs1,#imm` 等 7 条 + `LDI`），**新增 `MOV Rd,Rs`**。v1 §8 的"没有立即数算术"一节作废——位宽与通路两个障碍同时消失。
5. **`ALU.B` 上多了 `BSrc` mux**（选 `Rs2` 或 `imm8`）；`ALU.A` 反而变成**一根没有 mux 的直连线**（恒接 `Rs1`）。**这与 v1 正好相反**：v1 的 `ALUSrc` 选的是 A、`ALU.B` 是直连，因为那时 `[8:6]` 同时承担"第一源"和"立即数"、两者都得进 A；本版立即数有了自己的字段 `[7:0]`，自然挂在 B 上。
6. **PASS 由 1 个方向扩成 2 个**：`fn=0111` 是 PASS.A（`Result ← A`，供 `MOV`/`LD`/`ST`/`OUT`），`fn=1000` 是 PASS.B（`Result ← B`，供 `LDI`/`LDA`/`STA`）。
7. **opcode 重排**：`0000` ALU 寄存器型、`0001` ALU 立即数型，其余顺延；`LDI` 不再独占 opcode（它是立即数型 + PASS.B）。11 个用掉、5 个保留。
8. **四条访存指令的 `Rd` 统一为"数据寄存器"**（`LDA`/`STA`/`LD`/`ST` 的 `Rd` 都在 `[15:12]`、含义一致）。v1 §4 "两处载荷寄存器不在 `[8:6]`"的例外清单整条不复存在。
9. 助记符随之调整：`STA addr,Rs` → **`STA Rd,addr`**、`ST [Rs],Rd` → **`ST Rd,[Rs1]`**（`Rd` 统一写在前面）。
10. **周期行为、三读口硬接线、下降沿写口、前递/停顿结构与 v1 一致**，只有位段编号随字段变化（`[8:6]`→`[11:8]`、`[5:3]`→`[7:4]`、`[11:9]`→`[15:12]`）；"本指令是否写寄存器"的判据由 `rd≠0` 改用 **`RegWrite`**。
11. **正文里"v1 如何如何"的对照全部删去**，只留面向当前 ISA 的规则；改动经过即本节。

**v2（2026-09-19）——随 `isa.md` v2 全线改为 16 寄存器 / 24 位定长指令。**

改动清单与理由见 `isa.md` §11；这里只记本文档的对应变化。

- **位段全线替换**：opcode `[15:12]` → `[23:20]`；fn `[2:0]` → `[19:16]`；rd `[11:9]` → `[15:12]`；rs1 `[8:6]` → `[11:8]`；rs2 `[5:3]` → `[7:4]`；imm/addr 仍在 `[7:0]`。流水线寄存器宽度随之变为 **ID/EX 56、EX/MEM 26、MEM/WB 24**（IF/ID 存 `Inst[23:0]`）。
- **§2.1 寄存器堆 8×8 → 16×8**：读/写地址 3 位 → 4 位，写译码 3→8 改 4→16；**R0 由"恒 0（无寄存器）"改为普通寄存器**，"地址 0 那路接常量 0"整段接线警告删除，§1 的复位项补上"寄存器堆清 0"。
- **§2.1 "为什么是 3 个读口"的账重算**：v1 的理由（`STA` 的源被挤在 `[11:9]`、3 读口省元件）在 v2 不成立——同时要读的最多只有 2 个，元件数与"2 读口 + 地址 mux"**打平**。留 3 个口的理由换成**硬接线让冒险检测与 EX 前递直接比较裸字段**，且明说这是"宁可多摆 mux 也要保住判定逻辑"的一处。
- **§3.3 整段重写**：`ALU.A` 变成没有 mux 的直连线，`ALU.B = BSrc ? Imm : B_mux_out`——**`BSrc` 选的是 B，与 MIPS 的 `ALUSrc` 一致**；v1.5 那条"教科书选 B、本设计正相反"的警告随 v2 作废。`ALUSrc` 一并改名 `BSrc`（§3.1 / §3.8 / §2.7 / §7）。
- **§2.2 的 `PASS` 拆成两个码**：`0111 = PASS.A`（`MOV`/`LD`/`ST`/`OUT`，操作数在 A）、`1000 = PASS.B`（`LDI`/`LDA`/`STA`，立即数在 B）；`ALUop` 由 3 位改 **4 位**。理由写成"最少硬件的搬运通路"——不是为省 opcode（还剩 5 个）。
- **§3.5 `CWrite` 改式**：`(opcode == 0000) && !fn[2]` → **`(op == 0000 || op == 0001) && !fn[3] && !fn[2]`**（v2 多了立即数型 ALU 运算，也要写 C）。§3.8 的控制生成表随之多一个或门。
- **§3.1 的位重叠表整段删除**：v2 字段不重叠，`isa.md` §4 写成了"字段没有重叠"。但 **§5.2 的"误停"现象仍在**，成因改写为"未用槽位装着目标寄存器号或地址位"，结论与判据一字不变。
- **§3.2 / §3.4 / §3.6 / §4 / §5.1 的口与字段改动**：`BZ`/`BNZ` 的判零源由 C 口（`[11:9]`）改为 **A 口（`[11:8]`）**，§5.1 分支操作数 mux 的优先级 3 输入随之改接 `ReadDataA`；`LDA`/`STA` 的地址由 A 侧改到 **B 侧**（`BSrc=1` + `PASS.B`）；四条访存指令的 `rd` 统一为"数据/目标寄存器"，§3.2 里"两处载荷寄存器不在 `[8:6]`"那段删除。
- **冒险判据一律由 `rd≠0` 改 `RegWrite`**（§4 / §5.2 / §4.2）：R0 在 v2 是可写寄存器，`rd=0` 不再等于"不写"。
- **§2.4 ROM 256×16 → 256×24**（Data Bit Width = 24，`.mem` 由 4 位改 6 位十六进制），并加一条"搭建时先确认 ROM 组件接受 24 位宽"的提示。
