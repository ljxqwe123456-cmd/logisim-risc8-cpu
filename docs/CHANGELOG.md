## isa.md 的改动记录

**v2.7（2026-09-21）——§6 补「助记符大小写不敏感」。编码、控制信号与全部机器码一字未动。**

- **§6 原先只承诺了寄存器名大小写不敏感**（`r1` 等同 `R1`），但汇编器对助记符也做了 `upper()`，`add r1, r2, r3` 一直能汇编。补上这一条，免得读者以为助记符必须大写。

**v2.6（2026-09-21）——采纳 v2.5 记下的那条路：两条 store 的数据源移进自己空着的源槽，`[15:12]` 从此只写不读。`ST`/`STA` 的机器码全变，指令语义与全部判据值一字未动；`datapath.md` 同步为 v2.8。**

- **编码表两条 store 换布局**：`STA Rs,addr` 的数据源由 `[15:12]` 移到 `[11:8]`，`ST Rs,[Rs1]` 的移到 `[7:4]`，两条的 `[15:12]` 恒编 0；助记符里那个具名寄存器随之由 `Rd` 改称 `Rs`（它是**源**）。§4 的编码公式、位模式实例（新增 `ST`/`STA` 两条）、§6 的操作数顺序说明、§8 的两张控制表同步。
- **§4 那一小节整体重写**：原「为什么 store 的数据寄存器占的是 `rd` 槽」按"备选、未采用"写成，现改为「目标恒在 `[15:12]`，两条 store 的数据源各占自己的源槽」——目标之所以钉死在那格，是因为写口地址硬接线到 `[15:12]` 的锁存副本（没有 `RegDst` mux），能挑位置的只有 store 的源。原先论证"共享是被 opcode 预算逼出来的"那一段保留（它现在证明的是"数据源必须借用源槽"），三读口占用表换成两读口，删去"`[15:12]` 买到的主要是读起来顺"与"不采用那条路的代价"两段（那条路已是现行设计）。
- **§4「操作数在哪个槽」由三读口改两读口**：删掉 C 口一列，`STA`/`ST` 的写数据分别落在 A 口 / B 口，"四条访存指令 `Rd` 含义一致"那句改成"写目标恒在 `[15:12]`、源只在两个源槽里"。
- **§9 的三套网络对照表**：A/B/W **三个**前递 mux 改为 A/B **两个**，`dep` 的比较字段由三个减到两个。
- **`fn` 表 / `PASS` 表 / §8 实现说明里的 store 说明**按新通路改写：`STA` 的写数据经 A 前递 mux、`ST` 的经 B 前递 mux（§8）；`PASS` 对照表加一行对照项，说明 `STA` 的数据源虽然也在 A 口上，但它不经过 ALU。
- **「字段没有重叠」补一句**：没有任何一条指令既带 `rs2` 又带立即数，所以"源"与"立即数位"两种身份在同一格里永不共存（逐字段盲比仍会拿立即数位去比，那只造成多停，见 `datapath.md` §5.2）。
- **§4「目标恒在 `[15:12]`」那节补上"这条性质为什么值钱"**：原先只列了三处收益（读口 2 个 / `dep` 2 个比较器 / 写数据不必自带前递 mux），没点破它们共同的来源是"读口与比较网络都硬接线 ⇒ 某一格可能装源就等于要为它常驻配一套读 + 比"，读者容易把"源放哪一格"当成纯记法问题。同时点明**吃这份差价的只有数据通路，译码器不涉及**（控制信号只由 `op`/`fn` 生成）。

**v2.5（2026-09-21）——§4 补「两条 store 各用自己的空格子」这条路的完整账；编码表、指令语义与全部机器码一字未动。**

- **§4「借用现成的空格子」那一段原先不完整**：它只答了"两条 store 的空格不是同一格 ⇒ 交集只有 `[15:12]`"和"强行统一到 `[11:8]` 会连累 `ST` 的地址寄存器"两种排法，**没答"那就各用各的格子"**——而那两格各自正对一个硬接线的读口，读得到。补上：写数据通路加一个 `(MemWrite ∧ BSrc) ? A_mux_out : B_mux_out` 的二选一即可（`BSrc` 对 `STA` 恒 1、对 `ST` 恒 0，用现成控制位选，不新增流水线字段），前递的比较字段仍是固定位段；收益是 `[15:12]` 从此不当源 ⇒ `dep` 少一个比较器、**读口可以从 3 个减到 2 个**（连 `ReadDataC` 与 W 前递 mux 一起省掉）。**并写明 `[15:12]` 这个"统一"买到的是"读起来顺"（不是正确性、也不是速度），不采用那条路的理由是"重编 + 判据体系重做"的代价远大于几个便宜元件，不是硬件上做不到。**

**v2.4（2026-09-20）——§4 补「为什么 store 的数据寄存器占的是 `rd` 槽」、§9 改正「比较一律取裸字段」的说法、全文把角色名「生产者/消费者」换成「写 Rd 的那条 / 读 Rd 的那条」；编码表、指令语义与全部机器码一字未动。**

- **§4 在「字段为什么这样排」之后新增一小节**：读者看懂了流水线之后反过来会问"既然 `ST`/`STA` 的 `rd` 槽装的是源，为什么不挪个格子"。补上完整论证：ALU 立即数型整满 24 位 ⇒ `rs2` 与"必须参与比较的角色"里至少一个要住进立即数字节 ⇒ **比较字段与立即数位重叠是这个 ISA 的固有性质**（不是接线疏忽）；要给 store 数据单独开一格需要字节外三个互斥半字节，连扁平 opcode 也只剩 4 位（16 个），装不下 18 条助记符 ⇒ **共享是被 opcode 预算逼出来的**；并说明换排法只是把重叠挪到地址寄存器头上。现状胜出在三条：`[15:12]` 是唯一每个 opcode 都是寄存器号的字段、`ID/EX.rd` 一物两用省一个 4 位流水线字段、被重叠的 `[7:4]` 只对一个指令类是真源。
- **同节钉死一处易记错的事实**：**`STA` 没有地址寄存器**——它的地址就是立即数 `addr[7:0]`，只有 `ST` 才是"地址寄存器 + 数据寄存器"。
- **同节补「借用现成空格子」这一路的答复**：原文只论证了"**单独开一格**要付 4 位 opcode 的代价"，没答"**ST / STA 本来就有空格子**，为什么不用"。补一张三读口占用表：`ST` 空的是 `[7:4]`、`STA` 空的是 `[11:8]`，两条 store 的空格**不是同一格**，硬接线（无读口地址 mux）下交集只有 `[15:12]`；而它之所以在两条 store 里都空着，正因为它是目标寄存器槽、store 不写寄存器。
- **同节补 `rs2` 取高半字节的依据**：假命中的条件是写 Rd 的那条的 `rd` 等于这一格所代表的立即数半字节，半字节取值越集中、能撞上的目的寄存器越少。给出 `examples/` 的实测分布（49 个 8 位立即数/地址操作数：高半字节 5 种取值、低半字节 11 种）。
- **§9 改正一处与 §4 自相矛盾的说法**：原文写"所有比较用的寄存器编号都取**裸字段** `Inst[11:8]` / `[7:4]` / `[15:12]`"。这对 ID 段那两套网络（`dep`、分支操作数 mux）成立，对 **EX 段那三个 A/B/W 前递 mux 不成立**——它们比的是 `ID/EX.rsA` / `rsB` / `rd`，即同样三个位段的**锁存副本**，因为读 Rd 的那条进 EX 时 `IF/ID` 早已换成后面第四条指令（`datapath.md` §2.7）。补一张三套网络的对照表，并点明分界是"读 Rd 的那条此刻在哪一段"、这两组线别接混。
- **§9 判据句"在 EX 段用"的名单改正两处**：原文列"ALU 族/LD/ST/STA/OUT"，① 把**漏掉的 ALU 立即数型**补回来——`ADD R1,R2,#5` 读 `rs1`，确实在 EX 段用；② 例外从只写 `LDA` 改成 **`LDI`/`LDA`** 两条——`LDI` 同样是 `BSrc=1` → `PASS.B`、A 口那份读数不参与运算，也一个寄存器都不读。名单与 `datapath.md` §4.2 表首行、`CLAUDE.md` 冒险表首行**三处同步**（原先三处措辞各不相同：一处"ALU 族"、两处"R 型"）。
- **§4 精确化 `[7:4]` 的取值描述**："其余场合它装的是立即数高半字节"不准确——`LD`/`ST`/`MOV`/`OUT`/`HLT` 的 `[7:4]` 是 **0**，不是立即数位。改成"立即数/地址的高半字节、或 0"。
- **全文换掉角色名「生产者/消费者」**：原文用"生产者 / 消费者"指 RAW 的两端，但这组词① 不含"写/读哪个寄存器"的信息，② 容易被读成"凡是被读到的都算消费者"——而 `LDA` 一个寄存器都不读、`ST`/`STA` 是读寄存器却**不写**寄存器，正是靠这两处把词义带偏的。改成自述式的「**写 Rd 的那条 / 读 Rd 的那条**」，凡出现处一律用全称、不再缩写。（`isa.md` §2 里"ID 段的全部消费者"是**扇出**义、与 RAW 角色无关，改作「取用方」以免撞名。）
- **§9 三套网络对照表补上停顿条件里漏掉的一处比较**：表里 `dep` 行的"写 Rd 的那条那一侧"只写了 `ID_EX.rd`，但**停顿条件不只有 `dep` 这一项**——③ 的 k=2 那半（分支的源被关在在飞的 load 里）比的是 **`EX/MEM.rd`**，`datapath.md` §5.2 的代码里就是这么写的。补上后该行的读侧也标清了"`dep` 三个字段全比，② / ③ 只比 `Inst[11:8]`"。
- **§9 判据句补上 load 那一格**：原句"在 EX 段用 → 前递 + 下降沿写口"漏了写 Rd 的那条是 load 的情形——load 的值要到它自己走完 MEM 段才可用，`k=1` 那一格 `EX/MEM` 里只有地址、前递取不到值，**只能停 1 拍**。`datapath.md` §4.2 的同一处已补成独立一行。
- **§9 区分「读」与「用」并补 `LDA` 的例外**：原判据句只写"在哪一段**用**这个值"，容易被读成"在哪一段**读寄存器堆**"——三个读口其实一律在 **ID** 段读，到 EX 才判效期、才由前递 mux 换掉。补上这层，并点明 **`LDA` 的地址是立即数、一个寄存器都不读**，所以它不在"在 EX 段用"那一列（`STA` 在列，因为写数据来自 `[15:12]`）。

**v2.3（2026-09-20）——补几处"为什么"；编码表、指令语义与全部机器码一字未动。**

- **§4 的 `fn` 段补"那九条靠什么干活"**：原文只说了"非 ALU 指令的 `fn` 硬件根本不看"，读者会顺着问"那它们的功能去哪了"。补上：它们的动作（`Result ← A` / `Result ← B`）**根本没有编码在指令里**（`fn=0000` 已被 `ADD` 占用），只能由译码器按 `op` 造常量——并点明 `op` 是功能选择器、`fn` 只是两个 ALU 族内部的子选择器。
- **§8 补"访存为什么不用一根线"与"`MemToReg` 为什么必需"**：原文只写了 `MemRead` 不接 RAM、`MemToReg` 是写回 mux 的选择端，没挡住"要么读要么写、为什么不合并"和"为什么非得多一个 mux"。补上：访存是**三态**（11 条指令两样都不是），且 `MemWrite` 是 RAM 真引脚、`MemRead` 是延迟标记，两者不对称；`MemToReg` 必需是因为 `LDA`/`LD` 的 `ALUResult` 是**地址**不是数据。表行本身的值一格未改。

**v2.2（2026-09-19）——补几处说明；编码表、指令语义与全部机器码一字未动。**

- **§7「`CWrite` 的生成式」补"为什么需要一个写使能"**：原文只回答了"哪四条写 C"和"两道门怎么分工"，没回答**为什么不能每拍都写 C**。补上：ALU 每拍都在算，非加减指令那几拍的 `Cout` 是垃圾；C 与寄存器堆 / RAM / PC 同属架构状态、各有一个写使能守门，少了它只有紧邻的 `ADD`→`ADC` 碰巧对。同一段也写进了 `datapath.md` §2.3。
- **§8 `ALUop` 定义写明确**：原文只写"ALU 功能码（ALU 族取 `fn`）"，容易被读成"`ALUop` 就是 `fn`"，进而把"非 ALU 指令 `fn=0`"读成"它们做加法"。补上"**是生成的控制值、不是字段本身**"。§4 字段表里 `fn（ALU 功能）` 随之改为 `fn（ALU 族的功能码）`。
- **§4 补「fn 表」**：原文只在 §5 有 `fn` 的语义表，§4 编码总览里查不到"某个 `fn` 值对应哪条助记符"。补一张**编码视图**的 `fn` 表（`fn` × 寄存器型/立即数型各自写成什么），语义仍只在 §5 讲一遍；并点明非 ALU 指令的 `fn` **硬件完全不看**（不是"默认加法"）。
- **§4 opcode 表把 `MOV` / `LDI` 列进助记符**：18 条助记符只占 11 个 opcode，原表两个 ALU 行只写"（见 §5）"，导致在表里找不到 `MOV`。表末补一句说明它们各住哪个 `fn`。
- **§4 数错了**：表末原写"11 个 opcode 装下 **15** 条助记符"——15 是 §8 控制表的**行数**（7 条 ALU 运算的两型各并一行），助记符本身是 **18** 条。改成 18 并说明 15 是怎么来的。
- **§5 补「`fn` 与 `ALUop` 的关系」**：§5 是 `fn` 的语义章节，却没写 `fn` 怎么到 ALU 上——「`fn` 只出现在 `ALUop` 生成式的 `op0\|op1` 那一支，其余九条拿到的是常量 `PASS.B`/`PASS.A`」补成一张三行对照表。原来那句"非 ALU 指令的 `ALUop` 因此不是默认加法"改为直接问"为什么用 `PASS` 而不是加 0"，避免与新增段落说同一件事。
- **§10 补"程序里怎么空一拍"**：汇编器没有 `NOP` 助记符（保留 opcode 是硬件内部用的），软件空操作要写 `MOV Rd,Rd`，并提醒别拿 `ADD Rd,Rd,#0` 凑（它是 ADD、会写 C）。
- **§10 补"为什么全 0 当不了 NOP"**：关键不是 R0 可写，而是 `ADD` 的 `CWrite=1`——**就算 R0 改回恒零也仍然是写 C**，MIPS 那套做法依赖"没有状态标志"。
- **§4 补"表里没有的东西"**：点明**没有间接跳转**（子程序因此写不出来）、没有 `CALL`/`RET`/`PUSH`/`POP`，以及栈可以纯软件搭；并写清加间接跳转**编码上零成本、代价全在数据通路上**（PC 多一路源、多一类 ID 段 RAW 冒险、`CALL` 还要传 `PC+1`）。
- **§4 补「字段为什么这样排」**：原文只解释了 24 位这个**宽度**是怎么来的，没说 **op/fn 为什么占最高位**。补上两条硬约束（imm/addr 占连续低 8 位、寄存器号半字节对齐）与三条讲究（控制位与数据位分半、十六进制与助记符同序、fn 放低位会退回 v1 的位重叠）。
- **§5 补两处取舍**：`NOT` 不做不是没位置（`fn` 还剩 7 个码），而是 `XOR Rd,Rs1,#0xFF` 已经是一条指令；非 ALU 指令的 `ALUop` 用 `PASS` 而非"默认加法"的理由写全（后者需要恒零寄存器与特判）。

**v2.1（2026-09-19）——第二轮对抗审查的修正；编码表、指令语义与全部机器码一字未动。**

- **§10「未编程 ROM 行为」写精确**：全 0 是 `ADD R0,R0,R0`，它执行 `R0 ← R0+R0` **并写 C**（`CWrite=1`），**不能当 NOP 用**——分支 flush 灌进 `IF/ID` 的常量必须取保留 opcode（`datapath.md` §6）。
- **§8 控制信号表**：BZ/BNZ/JMP/HLT 的 `ALUop` 由 `−` 改为 **`PASS.A`**（译码器那两级 mux 对它们只能落出 `0111`，表与 §8 的实现说明必须同值）。
- **§8 的 `MemRead` / `MemWrite` 行**改写：RAM 没有读使能脚，读是组合逻辑，`MemRead` 只是"本条在读 RAM"的标志。
- **§7 的 `CWrite` 生成式**写清两道门的分工：`op` 门挡住九条非 ALU 指令、`!fn[3] && !fn[2]` 挡住 `MOV`/`LDI`。

**v2（2026-09-19）——指令集重定义：16 位 → 24 位定长，8 个寄存器 → 16 个，二操作数 → 三操作数。**

一次改完，本文正文已全部按新 ISA 重写。要点：

1. **指令位宽 16 → 24 位**，字段改成半字节对齐的 `op(4) fn(4) rd(4) rs1(4) X(8)`。原先"立即数拆进 `[8:6]`/`[5:3]`/`[2:0]`"的**位重叠消失**——那是 v1 唯一一处"读错了电路照样跑对"的地方，本版没有了。
2. **寄存器 8 → 16 个**，`rd`/`rs1`/`rs2` 各占满一个半字节。
3. **R0 不再是恒零寄存器**，16 个全部通用可读写；汇编器不再禁止 `Rd=R0`。v1 §2 "读出恒 0 不是装饰"那段随之作废。
4. **新增立即数运算型**（`ADD Rd,Rs1,#imm` 等 7 条 + `LDI`），**新增 `MOV Rd,Rs`**。v1 §8 的"没有立即数算术"一节作废——位宽与通路两个障碍同时消失。
5. **`ALU.B` 上多了 `BSrc` mux**（选 `Rs2` 或 `imm8`）；`ALU.A` 反而变成**一根没有 mux 的直连线**（恒接 `Rs1`）。**这与 v1 正好相反**：v1 的 `ALUSrc` 选的是 A、`ALU.B` 是直连，因为那时 `[8:6]` 同时承担"第一源"和"立即数"、两者都得进 A；本版立即数有了自己的字段 `[7:0]`，自然挂在 B 上。
6. **PASS 由 1 个方向扩成 2 个**：`fn=0111` 是 PASS.A（`Result ← A`，供 `MOV`/`LD`/`ST`/`OUT`），`fn=1000` 是 PASS.B（`Result ← B`，供 `LDI`/`LDA`/`STA`）。
7. **opcode 重排**：`0000` ALU 寄存器型、`0001` ALU 立即数型，其余顺延；`LDI` 不再独占 opcode（它是立即数型 + PASS.B）。11 个用掉、5 个保留。
