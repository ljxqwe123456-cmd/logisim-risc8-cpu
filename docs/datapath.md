## 0. 顶层连接关系（文字框图）

```
        ┌─────────┐   Inst[23:0]    ┌─────────┐
  PC ──▶│ ROM     │───────────────▶│ IF/ID    │──▶ 译码 / 读寄存器 / 判零分支（ID）
        │ 256×24  │                │ (24bit)  │
        └─────────┘                └─────────┘
                                        │
        ┌───────────────────────────────┘
        ▼
   ID/EX 寄存器 ──▶ EX(ALU + 前递mux) ──▶ EX/MEM ──▶ MEM(数据RAM) ──▶ MEM/WB ──▶ 写回寄存器堆
   ▲                                              │
   │  Forwarding Unit（EX/MEM、MEM/WB → EX）      │
   └──────────────────────────────────────────────┘
   Hazard Unit（停顿）＋ 分支 flush ＋ PC 控制
```

控制信号在 ID 译码产生，随 ID/EX → EX/MEM → MEM/WB 逐级锁存；数据（读出的寄存器值、ALU 结果、RAM 数据）也随级传递。

三条结构决定贯穿全文：

- 寄存器堆两个读口，地址硬接线到固定字段，全设计没有读口地址 mux。
- ALU 有 PASS.A / PASS.B 两个直通功能，供"只搬运、不运算"的指令使用。
- 16 个寄存器全是普通寄存器，没有一个硬连线常量。冒险检测一律以"这条指令写不写寄存器"（`RegWrite`）为判据，不用 `rd≠0`。

**信号名约定**：`X_Y_字段` 表示"X/Y 级间寄存器里的字段"，位宽标在名字后（`Imm[7:0]`）。`ID/EX` 与 `ID_EX`、`IF/ID` 与 `IF_ID_Inst` 指的是同一个东西，两种写法混用只是为了让句子读起来顺。

## 1. 时钟与复位

- 单一时钟 `Clk`，上升沿触发所有寄存器（PC、IF/ID、ID/EX、EX/MEM、MEM/WB、C 标志、Output 寄存器）。
  - 唯一例外是寄存器堆的写口用下降沿（R0-R15 的 `Trigger` 设 `Falling edge`，做法见 §2.1）。原因见 §2.1 与 §4.1。
- 复位 `Rst`：PC ← 0；流水线寄存器清零（`ID/EX`/`EX/MEM`/`MEM/WB` 里装的是控制位，清 0 就是 NOP；`IF/ID` 里装的是指令字，清 0 是条 `ADD R0,R0,R0`，见 `isa.md` §10，但复位时全机状态同时清 0，它写回的仍是 0）；寄存器堆 R0-R15 ← 0；C ← 0；Output 寄存器（§2.8）← 0。
  - 寄存器堆也要复位。v2 里 R0 是普通寄存器，没有"恒 0"的硬连线，复位后它恰好是 0 是初值、不是性质；程序一旦写 R0 它就不再是 0。想让某个寄存器当零用，自己 `LDI`。
- 停机取 `MEM/WB.Halt` 做全局时钟使能：`ClockEnable = !MEM/WB.Halt`。它 =0 时所有时序元件（PC、四级流水线寄存器、寄存器堆、C 标志、Output 寄存器）停止更新，PC 与 OUT 保持不变。
  - 必须在 `MEM/WB` 取，不能提前。HLT 前面那条指令（通常是程序最后一条 `OUT`）要走到自己的 WB 拍才写回；在 ID 段一译出 HLT 就冻住等于提前掐时钟，最后一条 `OUT` 的显示会丢。等 HLT 自己流到 `MEM/WB` 时，它前面的指令都已经写完了。
  - 不要把 `ClockEnable` 拿去门控 `Clk` 本身（`Clk && !Halt` 那种接法）：那会破坏"单一时钟"的约定，而且 Logisim 里门控时钟容易报振荡。把 `ClockEnable` 扇出到各元件自带的 Enable 脚即可。
  - 各元件本来就有自己的使能条件，要和它相与：PC 是 `PCWrite && ClockEnable`，其余流水线寄存器是 `(各自的写使能) && ClockEnable`。
- 数据 RAM 写在上升沿；ROM / RAM 读、寄存器堆读口都是组合逻辑（Logisim 默认）。

## 2. 各模块接口

译码器（控制单元，ID 段）不单列接口表：它没有独立的数据输入，只吃 `Inst` 的两个字段、吐 §3.1 那 12 个控制信号，画法见 §3.8。

### 2.1 Register File（16×8，2 读口 + 1 写口）

| 方向 | 信号 | 位宽 | 说明 |
|---|---|---|---|
| in | ReadAddrA | 4 | 读口 A 地址 ← `Inst[11:8]` |
| in | ReadAddrB | 4 | 读口 B 地址 ← `Inst[7:4]` |
| in | WriteAddr | 4 | 写地址 ← `MEM/WB.rd`（不是 `Inst[15:12]`，理由见下） |
| in | WriteData | 8 | 写数据 |
| in | RegWrite | 1 | 写使能 |
| in | Clk / Rst | 1 / 1 | 时钟（下降沿）/ 复位（清 0） |
| in | ClockEnable | 1 | 全局停机使能，见 §1 |
| out | ReadDataA | 8 | 读口 A 数据 |
| out | ReadDataB | 8 | 读口 B 数据 |

实现：R0-R15 是 16 个完全一样的 8 位寄存器，没有一个是常量。两个读口 = 两个 16 选 1 mux 并排接同一组寄存器输出；写 = 4→16 译码 + `RegWrite` 门控。

没有"地址 0 那路接常量 0"这回事：16 个寄存器读写一视同仁，`LDI R0,#5` 会真的把 R0 写成 5。程序想要一个零，自己 `LDI Rd,#0`。

两个读口的地址硬接线，中间没有任何 mux：A 恒接 `Inst[11:8]`、B 恒接 `Inst[7:4]`。哪条指令用哪个口见 §3.2。

写地址跟读口不一样，它取自 `MEM/WB.rd`，不是 `Inst[15:12]`。读发生在 ID 段，那一拍 `IF/ID` 装的正是要读的那条指令，所以两个读口直连 `Inst` 的字段是对的；写发生在 WB 段，那一拍 `IF/ID` 早换成后面第四条指令了（§4.1 的时序表：WB 装 `00` 时 ID 装 `03`）。照 `Inst[15:12]` 接写地址，每条指令都会写到别人头上。正确接法是取 `rd` 的锁存副本：`Inst[15:12]` → `ID/EX.rd` → `EX/MEM.rd` → `MEM/WB.rd`（§2.7），写地址接最后这一级。这与 §4 前递 mux 用 `EX/MEM.rd`/`MEM/WB.rd` 比较、而不是拿 `Inst` 现取，是同一个道理。
> §8 第 4 步的单周期版本里没有流水线寄存器，`MEM/WB.rd` 还不存在，那时直接接 `Inst[15:12]` 是对的；加了流水线寄存器（第 5 步）之后必须改接 `MEM/WB.rd`。这是从第 4 步走到第 5 步时最容易原样照搬而漏掉的一根线。

为什么正好 2 个读口，而且不需要读口地址 mux：因为同时要读的寄存器最多 2 个，且只可能落在 `[11:8]` / `[7:4]` 两个字段上。R 型与 `ST` 读这两个（`ST` 的地址在 `[11:8]`、数据在 `[7:4]`），其余的一元指令最多读一个 `[11:8]`，`LDI`/`LDA`/`JMP`/`HLT` 一个都不读；`[15:12]` 是只写不读的目标槽（§3.2），没有哪条指令去读它。所以两个 16 选 1 mux 并排接上、地址线硬接这两个字段就够了，全设计没有一处读口地址 mux。

硬接线本身就是收益：源寄存器号恒等于两个固定位段（§4.2 / §5.2）。`dep`（§5.2）与 EX 段那两个前递 mux（§4）因此直接比字段就行，不必先算出"这一拍那两个口在读哪两个字段"——那个中间量随指令类型变化，逻辑会立刻从两个比较器涨成一张要跟着 ISA 一起维护的小真值表。

这里的 `ReadAddrA/B` 与 §2.7 的 `ID/EX.rsA`/`rsB` 是两组不同的线：前者由 ID 段当前的 `Inst` 驱动、喂给寄存器堆；后者是同样两个位段的锁存副本，随指令走到 EX 段供前递比较（§4）。内容一样，但分属两段——把 `ReadAddr` 接到 `ID/EX` 的副本上，ID 段读到的就是上一条指令的寄存器号。

写口用下降沿，不是上升沿。本模块是全设计唯一一处要动时钟的地方。§1 说"单一时钟、上升沿触发"，但寄存器堆若也按上升沿写，会出现"间隔正好 3 条指令"的 RAW 读错（完整分析见 §4.1）。做法：把 R0-R15 这 16 个 `Register` 组件的 `Trigger` 属性设成 `Falling edge`（Logisim-Evolution 的 `Register` 有 rising / falling / high / low 四档，默认 rising）。等价做法是给这 16 个寄存器接一根反相后的 `Clk`，但改属性少一个门、时钟网上也不多一个反相节点，优先用属性。

其余所有寄存器（PC、四级流水线寄存器、C 标志、Output 寄存器）与数据 RAM 一律保持上升沿。

Logisim 里没有现成的寄存器堆组件——Memory 库只有各类触发器、`Register`、`Counter`、`Shift Register`、`RAM`、`ROM`，其中的 `RAM` 是一读一写共用同一条地址线。所以上面那套"16 个寄存器 + 两个 16 选 1 mux"是自己搭出来的：两个读口来自两个 mux，不是组件自带的引脚。

### 2.2 ALU（8 位）

| 方向 | 信号 | 位宽 | 说明 |
|---|---|---|---|
| in | A | 8 | 操作数 A |
| in | B | 8 | 操作数 B |
| in | Cin | 1 | 进位入（接 C 标志） |
| in | ALUop | 4 | 功能选择（ALU 族取 `fn`；搬运类取 `PASS.A` / `PASS.B`） |
| out | Result | 8 | 结果 |
| out | Cout | 1 | 进位出（→ C 标志） |
| out | Zero | 1 | Result 全 0 为 1（本设计的分支不用它，见 §5.1） |

内部：一片 8 位加法器（A + B' + cin）加 AND/OR/XOR 逻辑门，结果 mux 选择。

| ALUop | 功能 | B' | cin | 结果 mux 取 | Cout |
|---|---|---|---|---|---|
| 0000 | ADD | B | 0 | A+B | 进位 |
| 0001 | ADC | B | Cin | A+B+Cin | 进位 |
| 0010 | SUB | ~B | 1 | A-B | 进位出（0=借位） |
| 0011 | SBC | ~B | Cin | A-B-(1-Cin) | 进位出（0=借位） |
| 0100 | AND | - | - | A&B | 0 |
| 0101 | OR | - | - | A\|B | 0 |
| 0110 | XOR | - | - | A^B | 0 |
| 0111 | PASS.A | - | - | A | 0（强制） |
| 1000 | PASS.B | - | - | B | 0（强制） |
| 1001-1111 | 保留 | - | - | - | - |

`B'` = B 与 `sub` 信号（ALUop ∈ {0010,0011}）异或得到；`cin` = ADD 取 0、ADC/SBC 取 Cin、SUB 取 1（由 ALUop 译码）。

按位化简后就是两根小线（照上表逐位推出来的，等价）：`sub = ~ALUop[3] & ~ALUop[2] & ALUop[1]`（只有 `0010`/`0011` 命中——`0110` XOR 虽然 `ALUop[1]=1`，被 `[2]` 挡掉）；`cin = ALUop[0] ? Cin : sub`（`ALUop[0]=1` 的恰好就是 ADC 与 SBC）。`cin` 对 OR / `PASS.A` / 保留码也会吐出 `Cin`，无害——那几码的结果不从加法器取、`Cout` 也被封着。

两个 PASS 是这套设计里最省事的两格：它们让 ALU 退化成一根线，于是"把某个操作数原样送到 `ALUResult`"不再需要"加 0"这种绕法。实现上就是结果 mux 多两路直连输入（A 一路、B 一路），加法器与逻辑门照旧不动。

"加 0"那条路要付三笔账，这是 v2 改用直通的原因：① 得有一个恒为 0 的操作数，也就是必须有一个恒零寄存器；② 加法器会吐出一个没人要的进位，得额外声明"访存 / `OUT` 别写 C"；③ `ST`/`STA` 的地址挂在 B 侧，还得再特判 `ALU.B = MemWrite ? 8'b0`。

所以 R0 不必是恒零常量（§2.1）：v2 的搬运全部走直通，没有任何一条指令需要"另一个操作数是 0"这个前提——`MOV`/`LD`/`ST`/`OUT` 取 A 侧、`LDI`/`LDA`/`STA` 取 B 侧（见下表的分配），要零就自己 `LDI Rd,#0`。

为什么要两个方向：因为搬运类指令的操作数本来就在两边各有一半。

| 直通 | 谁在用 | 那个值落在 |
|---|---|---|
| `PASS.A`（0111） | `MOV` / `LD` / `ST` / `OUT` | A 侧（`ReadDataA` = `[11:8]`） |
| `PASS.B`（1000） | `LDI` / `LDA` / `STA` | B 侧（`BSrc` 选中的 `Imm`） |

这不是为省 opcode（opcode 还剩 5 个没用），而是最省硬件的搬运通路：`ALU.B` 上那个 `BSrc` mux 本来就非有不可（立即数型 ALU 运算要它，见 §3.3），B 侧早已是一个可选节点；`ALU.A` 是一根直连线、不要钱。两个方向各多接一路结果 mux 的输入，就把四条加三条搬运指令全兜住了，不需要任何额外的 mux 或通路。

`Cout` 那一位在 `ALUop >= 0100` 时与 0 相与（含两个 PASS），是防御性写法、不是正确性要求。写 C 的只有 `op0`/`op1` 里 `fn[3:0] < 0100` 的那四条（§3.5），加法器就算在 A 有值时吐出垃圾进位也进不了 C，所以这一位在单步验 ALU 时看不出来。接上它只是让"这条不写 C"在 ALU 一处也看得见，不必绕到 §3.5 的生成式去推。门是 `~ALUop[3] & ~ALUop[2]`，不能只写 `~ALUop[2]`——那会漏掉 `1000`（`PASS.B` 的 `ALUop[3]` 是 1）。

逐码验法（§8 第 2 步；直接拿常量喂 A / B / Cin，看 `Result` 与 `Cout` 两个 LED。第 8 步之前没有 C 寄存器，`Cout` 只看 ALU 自己的输出脚）：

| ALUop | A | B | Cin | Result | Cout | 这一行在验什么 |
|---|---|---|---|---|---|---|
| 0000 ADD | 0x0F | 0x01 | × | 0x10 | 1 | 进位出 |
| 0001 ADC | 0x0F | 0x00 | 0 / 1 | 0x0F / 0x10 | 0 | `Cin` 真的进了加法器 |
| 0010 SUB | 0x01 | 0x02 | × | 0xFF | 0 | 借位时 C=0 |
| 0011 SBC | 0x10 | 0x01 | 1 / 0 | 0x0F / 0x0E | 1 | 减的是 `(1-Cin)`，不是借位标志本身 |
| 0100 AND | 0xA5 | 0x0F | × | 0x05 | 0 | |
| 0101 OR | 0xA5 | 0x0F | × | 0xAF | 0 | |
| 0110 XOR | 0xA5 | 0x0F | × | 0xAA | 0 | |
| 0111 PASS.A | 0x5A | 0xF0 | × | 0x5A | 0 | B 取什么都不影响结果 |
| 1000 PASS.B | 0xF0 | 0x5A | × | 0x5A | 0 | A 取什么都不影响结果 |

每行的 Cin 只在该码真的用它时才给两个值（`×` = 该码内部忽略这个脚）。加粗那两行的 A / B 是挑过的：同一行里"加法器和、三个逻辑门、A 直通、B 直通"这六路候选值互不相同，所以任何一路选错（结果 mux 的译码接错、两个 PASS 方向接反）都会露出一个不同的值。别随手换成 0 / 0xFF 这类数——例如 `A=0xF0, B=0x0F` 时 OR、XOR、`A+B` 三者都等于 `0xFF`，接错也看不出来。

### 2.3 C 标志（1 位状态寄存器）

| 方向 | 信号 | 说明 |
|---|---|---|
| in | Cout | ALU 进位出 |
| in | CWrite | 写使能，仅 ADD/ADC/SUB/SBC 时为 1（随 ID/EX 锁存，见 §2.7） |
| in | Clk / Rst | 时钟 / 复位（清 0） |
| in | ClockEnable | 全局停机使能，见 §1 |
| out | C | 进位标志（→ ALU 的 Cin） |

它不在 ALU 里，而是 §2.2 那块子电路之外的一个独立 1 位寄存器：ALU 的接口表里没有 `Clk`、没有 `CWrite`——ALU 是纯组合的，`Cout` 是它吐出的一根线、`Cin` 是喂进去的一根线，两者在顶层用这个寄存器接起来（`Cout` → `D`，`C` → `Cin`）。别图省事把它画进 ALU 子电路：`Cin` 会变成内部节点，§2.2 末的逐码验法（手工拿常量喂 `Cin` 验 ADC/SBC 那两行）就没法做了，`Clk` / `Rst` / `ClockEnable`（停机要把它一起冻住，§1）也得跟着挤进 ALU 的接口。这也是 §8 把 ALU 排在第 2 步、C 寄存器排在第 8 步的原因——中间那几步 `Cin` 先接常量（第 2 步按 §2.2 的表手工改它，此时还没有谁自动写 C）。

- `Cout` → C → `Cin` 绕回 ALU 看着像个环，但中间隔着寄存器，是跨拍的，Logisim 不会报振荡。若真报振荡，说明你把寄存器漏了——多半是直接把 `Cout` 接到了 `Cin` 上（那才是组合环，且 AND/OR/PASS 那几拍会锁死）。
- C 在 EX 段读写，不需要前递：C 由 EX 段的 ALU 算出并在该拍末尾写入；下一条指令下一拍才进 EX 来读它，正好读到新值（多字节 ADD/ADC、SUB/SBC 正是靠这个时序串起来的）。C 只在 EX 被读、只在 EX 被写，无跨级冒险。
- 为什么需要一个写使能：ALU 每拍都在算，`Cout` 每拍都有值——`AND`/`LDA`/`OUT` 那些拍里加法器吐出的进位是无效值。C 是架构状态，和寄存器堆（`RegWrite`）、RAM（`MemWrite`）、PC（`PCWrite`）一样，只在指令明确声明要改它时才更新。少了 `CWrite`，C 就退化成"上一拍 ALU 加法器的副产物"，只有紧邻的 `ADD`→`ADC` 才碰巧对；中间夹一条 `ST`/`OUT`/`LDI`（它们那拍也在跑 ALU）就把进位冲掉了。
- `CWrite` 必须随 ID/EX 锁存、并被气泡清零：气泡是把 ID/EX 的控制信号全部清零（`ALUop` 也随之变 `0000` = ADD），而 ALU 仍在拿 ID/EX 里残留的 `ReadDataA/B` 做运算、`Cout` 是无效值。若把 `CWrite` 组合译码成"`ALUop` 是加减"，气泡就会把无效值写进 C。见 §3.5。

### 2.4 Program ROM（256×24）

| 方向 | 信号 | 位宽 |
|---|---|---|
| in | Address | 8（= PC） |
| out | Inst | 24 |

Logisim 设置：Data Bit Width = 24，Address Bit Width = 8。右键 → Load Image 载入汇编器生成的 `.mem` 文件（`v2.0 raw` 格式：首行 `v2.0 raw`，随后按序 6 位十六进制值、空格分隔）。

> 搭建时先确认这一条：把 ROM 的 Data Bit Width 设成 24 之后，Load Image 能不能吃下 6 位十六进制的字。这是 v2 唯一一处"文档没法替你验"的设置——它取决于 Logisim 版本的 ROM 组件，不是本设计的选择。真的不接受 24，再回来商量把指令宽度补到 32 位（字段位置全部不变，只是每条指令多 8 位保留位、`.mem` 变 8 位十六进制）。

### 2.5 Data RAM（256×8）

| 方向 | 信号 | 位宽 |
|---|---|---|
| in | Address | 8 |
| in | DataIn | 8 |
| in | MemWrite | 1 |
| in | Clk | 1 |
| out | DataOut | 8 |

读为组合逻辑，写在上升沿且 MemWrite=1。**RAM 没有读使能脚**，所以 `MemRead` 不接它（见 `isa.md` §8）。

### 2.6 IF 段（PC + 增量器 + 目标选择）

时序部分只有一个 PC，其余三个都是组合部件。

| 方向 | 信号 | 位宽 | 说明 |
|---|---|---|---|
| in | PCNext | 8 | 下一 PC 值，来自下面的目标 mux |
| in | PCWrite | 1 | 0 时 PC 保持（停顿）。接 PC 的 Enable 脚 |
| in | ClockEnable | 1 | 全局停机使能，见 §1。`PC 的 Enable = PCWrite && ClockEnable` |
| in | Clk / Rst | 1 / 1 | 上升沿更新；Rst 清 0 |
| out | PC | 8 | → `ROM.Address`，同时喂给增量器 |

三个组合部件：

| 部件 | 输出 | 接法 |
|---|---|---|
| 增量器 | `PC+1` | 8 位加法器：A = `PC`、B = 常量 1 |
| 跳转目标 | `IF/ID.Inst[7:0]` | 直接从 IF/ID 切片，无需任何运算 |
| 目标 mux | `PCNext` | 2 选 1：`sel = branch_taken \|\| Jump`，sel=1 取跳转目标、sel=0 取 `PC+1` |

- 目标是绝对地址，不叠加 PC：`Inst[7:0]` 本身就是目标地址，mux 直接选它即可，不需要"PC + 偏移"那一级加法器。见 `isa.md` §4。
- `PCNext` 与 `PCWrite` 是两根独立的线，分别驱动 mux 和 Enable：`branch_taken` / `Jump` 只决定"下一拍去哪"，停顿（`PCWrite=0`）只决定"要不要动"。两者不要合并成一根。

### 2.7 流水线寄存器字段（统一列于此）

`IF/ID` 就是 IR（指令寄存器）——本设计没有单独的 IR 元件：指令在 ID 段就住在 `IF/ID` 里，译码器、寄存器堆的两个读口、判零分支都直接从它接线（§3.8 开头那张扇出表）。名字叫 `IF/ID` 是因为它同时充当 IF 与 ID 之间的级间寄存器。

| 寄存器 | 字段 |
|---|---|
| IF/ID | Inst[23:0] |
| ID/EX | RegWrite, MemToReg, MemRead, MemWrite, OutEn, Halt, CWrite, BSrc, ALUop[3:0], ReadDataA[7:0], ReadDataB[7:0], Imm[7:0], rsA[3:0], rsB[3:0], rd[3:0](=Inst[15:12]) |
| EX/MEM | RegWrite, MemToReg, MemRead, MemWrite, OutEn, Halt, ALUResult[7:0], WriteData[7:0], rd[3:0] |
| MEM/WB | RegWrite, MemToReg, OutEn, Halt, MemData[7:0], ALUResult[7:0], rd[3:0] |

位宽：ID/EX 48 位（超过 Logisim 寄存器上限 32，要拆成两个寄存器装，见下）、EX/MEM 26 位、MEM/WB 24 位——数 1 位的控制信号（ID/EX 8 个、EX/MEM 6 个、MEM/WB 4 个），再加上 `ALUop[3:0]`、各自的 `[7:0]` 数据字段与 `rd[3:0]`。

几个字段为什么只到某一级：

- `CWrite` 与 `BSrc` 只到 ID/EX。它们在 EX 段就消费掉了（写 C、选 `ALU.B`），不必往下传。
- `Jump` / `BranchZ` / `BranchNZ` 一格都不进流水线寄存器。它们在 ID 段就用掉了——驱动 PC 的目标 mux、并 flush `IF/ID`（§5.1 / §6）。
- `Halt` 恰好相反，必须一路锁存到 `MEM/WB`，因为停机是 WB 段才生效的（§1）。
- `OutEn` 到 WB 段才生效，要传到底。

规律是控制信号只锁存到"它被消费的那一级"为止。

没有第三路读数据要锁存：`ST`/`STA` 的写数据来自 A/B 两个前递 mux 的输出，在 EX 段现取（§3.6），所以 ID/EX 里没有 C 口的数据、也不需要它。

无 CALL/RET，故不传递 PC 值（未来加 CALL 再补）。

`rsA` / `rsB` / `rd` 是裸字段切片，不是 mux 输出：`rsA` 恒等于 `Inst[11:8]`、`rsB` 恒等于 `Inst[7:4]`、`rd` 恒等于 `Inst[15:12]`，三者直接接线，中间没有任何选择逻辑（§3.3）。

必须锁存这两个编号的原因：EX 段的两个前递 mux 要拿读 Rd 的那条自己的源寄存器号去和 `EX/MEM.rd` / `MEM/WB.rd` 比较（§4），这个比较发生在 EX，所以编号必须随 ID/EX 传过去，不能从 `Inst` 现取（IF/ID 那时早换成下一条指令了）。`rd` 也一并锁存，但它的去向是写地址链（§2.1），不参与前递比较。

前递 mux 的源就取前两个字段，一一对应：

| mux | 源字段 | 等于 |
|---|---|---|
| A | `ID/EX.rsA` | `Inst[11:8]` |
| B | `ID/EX.rsB` | `Inst[7:4]` |

#### 怎么把这些字段装进寄存器：分线器与位序

48 位装不进一个寄存器（Logisim 的寄存器上限 32 位），所以 ID/EX 用两个 32 位寄存器拼：甲装三个数据字节，乙装 8 个控制位 + `ALUop` + 三个寄存器号。两个都只用到低 24 位，高 8 位接常量 0。切法落在字段边界上，数据字节全归一个，控制位与三个寄存器号全归另一个。

位序本身是自由的，下面这张是本设计实际采用的那一种，照抄即可（括注是图纸上常用的短名）。

`ID/EX` 甲（32 位，全是数据；只用到低 24 位）——分线器：输入位宽 32、分支 3

| 分支 | 位宽 | 起始位 | 字段 |
|---|---|---|---|
| Bit 0 | 8 | 0 | `Imm[7:0]` |
| Bit 1 | 8 | 8 | `ReadDataA[7:0]`（RA） |
| Bit 2 | 8 | 16 | `ReadDataB[7:0]`（RB） |

`ID/EX` 乙（32 位，控制与编号；只用到低 24 位）——分线器：输入位宽 32、分支 12

| 分支 | 位宽 | 起始位 | 字段 |
|---|---|---|---|
| Bit 0 | 4 | 0 | `ALUop[3:0]` |
| Bit 1 | 4 | 4 | `rd[3:0]` |
| Bit 2 | 4 | 8 | `rsB[3:0]` |
| Bit 3 | 4 | 12 | `rsA[3:0]` |
| Bit 4 | 1 | 16 | `CWrite` |
| Bit 5 | 1 | 17 | `Halt`（HT） |
| Bit 6 | 1 | 18 | `OutEn`（OE） |
| Bit 7 | 1 | 19 | `BSrc`（ALUSrc） |
| Bit 8 | 1 | 20 | `MemWrite`（MW） |
| Bit 9 | 1 | 21 | `MemToReg`（MTR） |
| Bit 10 | 1 | 22 | `MemRead`（MR） |
| Bit 11 | 1 | 23 | `RegWrite`（RW） |

48 位字段装进 32 + 32 两个寄存器，与上表对得上。两个寄存器必须共用时钟、共用写使能，气泡时一起清零——漏清一个就是"半个气泡"，残留的控制位会让停顿条件误触发。

- 甲、乙的高 8 位（24-31）都没有字段：D 端各接一个 8 位常量 0。悬空会让总线上带 error（十六进制显示成 `E`），虽不影响低 24 位，但容易掩盖真问题。也可以干脆把这两个寄存器都做成 24 位。
- 分线器里填的是"起始位"这个数字，不是名字——名字只是给你在图上写标签用的。真正要保证的只有一条：D 端和 Q 端两个分线器的每一支，位宽与起始位都填得一样（配好一个复制粘贴过去）。
- 乙的位序是反着排的（越靠后的字段占越低的位）：从第 23 位往下念，正好是 `RegWrite, MemRead, MemToReg, MemWrite, BSrc, OutEn, Halt, CWrite, rsA, rsB, rd, ALUop`。分线器对话框里若从上往下列，就照这个顺序从上往下填。
- 调试时看乙的最低一位十六进制数就是 `ALUop`；8 个控制位在 16-23，即第 5、6 位十六进制数（`RegWrite` 在第 23 位、`CWrite` 在第 16 位）。

分线器（Splitter）属性：填输入位宽（甲乙两个都是 32）、分支数，再给每一支填位宽与起始位（该支最低位在总线里的下标）。每个寄存器要两个：一个在 D 端（宽端朝寄存器，把散线拼成总线），一个在 Q 端（宽端朝寄存器，把总线拆回散线）。Logisim 的分线器不分方向，同一份配置两头通用，所以配好一个复制粘贴过去，别配两遍。

`EX/MEM`（26 位）与 `MEM/WB`（24 位）都在 32 以内，各用一个寄存器即可，位序同样随你排。

排位序时最容易出错的地方：各支必须不重叠、不漏地铺满整个宽度（32 或 24）。重叠或漏掉不会报错——Logisim 照样仿真，只是某个字段拿到的是另一个字段的值，电路跑得欢、结果全错。

### 2.8 Output 寄存器（8 位，LED / 数码管显示）

| 方向 | 信号 | 位宽 | 说明 |
|---|---|---|---|
| in | DataIn | 8 | ← `MEM/WB.ALUResult`（为什么不能取 `MemData` 见 §3.7） |
| in | OutEn | 1 | 写使能，随流水线一路锁存到 WB 段才生效 |
| in | ClockEnable | 1 | 全局停机使能，见 §1 |
| in | Clk / Rst | 1 / 1 | 上升沿写入；Rst 清 0 |
| out | DataOut | 8 | → LED / 数码管 |

`OUT` 在 WB 段写它，所以显示值比该指令取指晚 4 拍——这是流水线的正常延迟。

`OutEn` 不能只在 ID 段用一下：它不是"取指那一拍有效"的脉冲，而是跟着 `OUT` 这条指令流过整条流水线的（§2.7 的三个流水线寄存器里都有它）。中间少传一级，写进去的就是别的东西。

## 3. 译码（ID 段）

### 3.1 控制信号

12 个控制信号的含义、逐条指令的取值、以及按 opcode 反查的转置表，都在 `isa.md` §8，这里不重复。本节只讲接线：某个信号由哪几个 `opN` 线或出来、译码器怎么画（§3.8），以及各条数据通路怎么被这些信号选中（§3.2-§3.7）。

本节反复用到的三个生成式（推导见 `isa.md` §8 与下文 §3.5）：

```
CWrite   = (op0|op1) && !fn[3] && !fn[2]
BSrc     = op1 | op2 | op3
ALUop    = (op0|op1) ? fn : ((op2|op3) ? PASS.B : PASS.A)
```

字段来源：op = `Inst[23:20]`；fn = `Inst[19:16]`；rd = `Inst[15:12]`；rs1 = `Inst[11:8]`；rs2 = `Inst[7:4]`；imm/addr = `Inst[7:0]`（`op=0000` 时 `[7:4]` 装 rs2、`[3:0]` 保留为 0；`op=0001` 时 `Inst[7:0]` 就是 imm）。

v2 的字段不重叠：`[7:0]` 这一格在寄存器型指令里只用到高 4 位当 `rs2`、低 4 位是保留的 0，在立即数型指令里整格是 `imm[7:0]`——两种含义互斥，由 `op[23:20]` 决定，不存在"同一根线身兼两义"的位段。

### 3.2 两个读口用哪个

地址硬接线，直接来自 `Inst` 的固定字段，没有 mux：

```
ReadAddrA = Inst[11:8]
ReadAddrB = Inst[7:4]
```

每条指令用到哪个口（括号里是该槽位实际编码进去的东西，没被消费的口读出来是垃圾，但无害）：

| 指令 | A `[11:8]` | B `[7:4]` | `rd[15:12]`（写目标） |
|---|---|---|---|
| R 型（ADD/SUB/AND/…） | rs1 → `ALU.A` | rs2 → `ALU.B` | = Rd |
| `MOV Rd,Rs1` | Rs1 → `ALU.A` | 0 → R0（没用） | = Rd |
| `ADD Rd,Rs1,#imm`（立即数型） | Rs1 → `ALU.A` | imm[7:4]（没用） | = Rd |
| `LDI Rd,#imm` | 0 → R0（没用） | imm[7:4]（没用） | = Rd |
| `LDA Rd,addr` | addr[7:4]（没用） | addr[3:0]（没用） | = Rd |
| `STA Rs,addr` | Rs → WriteData | addr[7:4]（没用） | 0（不写） |
| `LD Rd,[Rs1]` | Rs1 → 地址 | 0 → R0（没用） | = Rd |
| `ST Rs,[Rs1]` | Rs1 → 地址 | Rs → WriteData | 0（不写） |
| `BZ` / `BNZ Rs1,addr` | Rs1 → 判零 | addr[7:4]（没用） | 0（不写） |
| `OUT Rs1` | Rs1 → 显示值 | 0 → R0（没用） | 0（不写） |
| `JMP addr` | 0 → R0（没用） | addr[7:4]（没用） | 0（不写） |
| `HLT` | 0 → R0 | 0 → R0 | 0（不写） |

一条硬约定：目标寄存器恒在 `[15:12]`，源寄存器只可能出现在 `[11:8]` / `[7:4]`。`LDA`/`LD` 把写目标放在 `[15:12]`；`STA`/`ST` 的数据源放在自己空着的那个源槽里（地址占着另一个槽）；`BZ`/`BNZ` 的判零源就是普通的 `rs1` 槽（A 口），不是借来的槽位。`[15:12]` 全 ISA 只写不读，所以两个读口就够（§2.1），`dep` 也只比两个源槽（§5.2）。汇编器按这套约定编码，见 `isa.md` §4 的位模式实例。

> `ST`/`STA` 的数据源为什么放在源槽里：两条 store 各有一个槽是空着的（`STA` 的地址占 `[7:0]`，`[11:8]` 空着；`ST` 的地址占 `[11:8]`，`[7:4]` 空着）。把数据源放进这个空槽，`[15:12]` 就只剩"目标"一种角色。反过来 `LD`/`LDA` 的目标是被钉死的——写口地址硬接 `[15:12]` 的锁存副本（§2.1，全设计没有 `RegDst` mux），目标放别处就写不进去，所以能动的只有 store 的源。24 位预算与备选方案的账见 `isa.md` §4。
>
> 代价是两条 store 的写数据得在 EX 段从 A/B 两路里选一路（`MemWrite && BSrc` 二选一，§3.6）——比多摆一个读口 + 一路锁存 + 一个 W 前递 mux 便宜。
>
> 记号：`ST`/`STA` 的第一个操作数是数据源，本文写作 `Rs`；`LD`/`LDA` 的第一个操作数才是写目标 `Rd`。

"没用"的那些槽读到的是垃圾（地址高位、保留 0、别的字段），两个读口的地址线永远接着，只是读出来的数据没人消费。这不是设计缺陷，但有一个可观测的副作用：冒险检测比较的是裸字段，所以这些垃圾会让它误判出并不存在的依赖、多停 1 拍。只损失周期、不损失正确性，详见 §5.2 末。

"选哪个口"这件事发生在下游，而且几乎不花 mux。上面那张表里"每条指令用哪个口"是接线定死的（谁接到谁），不是译码器算出来的——译码器参与选数据的地方只有两处：

| 取用方 | 取哪只口的数据 | 怎么选 |
|---|---|---|
| `ALU.A` | A 口 | 直连（经 A 前递 mux，§4） |
| `ALU.B` | B 口读数 或 立即数 | `BSrc` 二选一（§3.3） |
| `WriteData`（`ST`/`STA` 的写数据） | `ST` 取 B 口、`STA` 取 A 口 | `MemWrite && BSrc` 二选一（§3.6） |
| 判零器（`BZ`/`BNZ`） | A 口 | 直连（经 ID 段 A 前递，§5.1） |
| Output 寄存器（`OUT` 的显示值） | A 口 | 直连（经 A 前递 mux，§4） |
| 寄存器堆的写地址 | `[15:12]` | 直连 |

写地址连 mux 都不需要：MIPS 要一个 `RegDst` mux 在 `rt` / `rd` 之间选，这里目标寄存器恒在 `[15:12]`，省掉了。把操作数钉在固定字段位上，是这类定长 ISA 的通用手法（MIPS 的两个读口地址同样是硬接线的），代价是编码时得迁就它。

真正拿 `rsA` / `rsB` 去"选"的 mux 在 §4 的前递单元：那两个 3 选 1 mux 的选择端确实由 `ID/EX.rsA` / `rsB` 参与算出来，但它们选的是数据从哪来（`EX/MEM` / `MEM/WB` / 寄存器堆），不是读口地址。想找"按 `rsA` 选读口"的函数是找不到的。

### 3.3 ALU 的两个输入

```
ALU.A = A_mux_out                     ; 没有任何 mux
ALU.B = BSrc ? Imm : B_mux_out        ; BSrc=1 仅 立即数型 / LDI / LDA / STA
```

（`A_mux_out` / `B_mux_out` 是 §4 两个前递 mux 的输出；`Imm` = `Inst[7:0]`。）

- `BSrc` 选的是 B，和 MIPS 的 `ALUSrc` 一样。立即数（或 `LDA`/`STA` 的绝对地址）从 B 侧进 ALU。
- `ALU.A` 是一根直连的线（只经过 A 前递 mux），没有任何二选一。
- B 这条路上串着两级 mux：先 §4 的 3 选 1 前递 mux（把 `ReadDataB` 换成前递值，得 `B_mux_out`），再这个 2 选 1 `BSrc` mux。A 只有前一级、没有第二级——所以上面写的"二选一"专指 `BSrc` 这一级。
- 这两个输入都不是译码器算出来的。数据线一根都不进译码器：它只为 `ALU.B` 那个二选一吐一根选择端 `BSrc`（随其余控制位一起锁进 `ID/EX`，§2.7），mux 本体画在译码器子电路外面、EX 段的顶层。`ALU.A` 更彻底——连选择端都没有。所以"某条指令的 A / B 各取什么"是 §3.2 那张表定死的接线，不是译码逻辑。
- `BSrc` 在 ID 段算、在 EX 段选：它是组合出来的控制位，跟着其余控制位锁进 `ID/EX`（§2.7），到 EX 才落到 mux 的选择端；`Imm` 与 `ReadDataB` 两个候选都要锁进 `ID/EX`（甲寄存器里的 `Imm` 和 `RB`），选择动作在锁存之后。
- 为什么不在 ID 段就选好、只锁一个 8 位操作数：因为 `BSrc` mux 必须待在前递 mux 后面（§4 的 B mux）。`LDI`/`LDA`/`STA` 的 `[7:4]` 是立即数/地址的位（§3.2 表里的"没用"），可它会被当成 `rsB` 去比对前递条件；把 `BSrc` mux 挪到 ID 之后，EX 段那个 B 前递 mux 就成了最后一级——一条紧邻的写指令只要 `rd` 恰好等于那个垃圾值，就会把前递值盖到立即数上（`LDI R12,7` 紧跟 `LDI R5,0xC0`，`0xC0` 的 `[7:4]` = `0xC` = R12，`OUT R5` 就会显示 `7`）。现在的次序（前递在前、`BSrc` 在后）让 `BSrc=1` 无条件压掉 `B_mux_out`，这类误命中天然无害——与 §5.2 末的"误停无害"是同一类。

逐条确认 A / B 各取什么：

| 指令 | ALUop | ALU.A 取自 | ALU.B 取自 |
|---|---|---|---|
| R 型 | `fn` | `ReadDataA` = rs1 | `ReadDataB` = rs2 |
| 立即数型 | `fn` | `ReadDataA` = rs1 | `Imm`（`BSrc=1`） |
| LDI / LDA | `PASS.B` | `ReadDataA`（未用槽位，垃圾） | `Imm`（`BSrc=1`） |
| STA | `PASS.B` | `ReadDataA` = 数据源（另有去向，见下） | `Imm`（`BSrc=1`）= 地址 |
| LD / OUT | `PASS.A` | `ReadDataA` = rs1 | `ReadDataB`（未用槽位，垃圾） |
| ST | `PASS.A` | `ReadDataA` = 地址 | `ReadDataB` = 数据源（另有去向，见下） |

两个 PASS 各自把"有意义的那个操作数"原样送到 `ALUResult`——`LDI`/`LDA`/`STA` 取 B（立即数 / 地址），`LD`/`ST`/`OUT` 取 A（地址 / 显示值）。对 ALU 来说另一侧被完全忽略，所以未用槽位读出什么垃圾都不影响 `ALUResult`——但两条 store 的那一侧并不白读，见下一段。

两条 store 的另一个操作数（数据源）与 ALU 毫无关系：它只是路过 `A_mux_out`（`STA`）或 `B_mux_out`（`ST`），由 §3.6 的写数据 mux 在进 ALU 之前就分流走了。所以"操作数在 A 还是 B"和"PASS 朝哪个方向"是两件独立的事。

为什么 `BSrc` 落在 B、`PASS.A` 给 A 侧的四条——因为读口地址硬接线（§2.1 / §3.2）：

- `LD` / `ST` / `OUT` 的操作数寄存器在 `[11:8]`，而 `[11:8]` 就是 A 口的地址线，这个值物理上只有 A 口读得到。所以这三条加 `MOV` 走 `PASS.A`。
- `LDI` / `LDA` / `STA` 要的是立即数/绝对地址，它挂在 `BSrc` mux 的 B 侧。所以这三条走 `PASS.B`。
- 立即数型 ALU 运算（`ADD Rd,Rs1,#imm`）两个操作数都要：rs1 从 A 口直连，imm 从 B 侧——`BSrc` mux 就是为它准备的，`LDI`/`LDA`/`STA` 只是顺带复用了同一个二选一。

一份硬件干三件事：`ALU.B` 上的 mux 本来就非有不可（立即数型要它）；四条访存指令的地址又全都从 `ALUResult` 走（`LDA`/`STA` 走 B 侧立即数，`LD`/`ST` 走 A 侧寄存器）——于是 MEM 段不必再有第二个地址 mux，`RAM.Address` 直接取 `EX/MEM.ALUResult` 即可（§3.6）。PASS 在这一拍的作用只是"别运算、原样放行"，把 ALU 的输出让给地址用。

### 3.4 各指令怎么凑出 `ALUResult`

| 指令 | `BSrc` | A | B | ALUop | `ALUResult` |
|---|---|---|---|---|---|
| `MOV Rd,Rs1` | 0 | `ReadDataA` = Rs1 | - | PASS.A | = Rs1 |
| `ADD Rd,Rs1,Rs2` | 0 | Rs1 | Rs2 | fn | rs1 op rs2 |
| `ADD Rd,Rs1,#imm` | 1 | Rs1 | `Imm` | fn | rs1 op imm |
| `LDI Rd,#imm` | 1 | - | `Imm` | PASS.B | = imm |
| `LDA Rd,addr` | 1 | - | `Imm` | PASS.B | = addr（绝对地址） |
| `STA Rs,addr` | 1 | `ReadDataA` = Rs（写数据，ALU 不用） | `Imm` | PASS.B | = addr |
| `LD Rd,[Rs1]` | 0 | `ReadDataA` = Rs1 | - | PASS.A | = 地址寄存器值 |
| `ST Rs,[Rs1]` | 0 | `ReadDataA` = Rs1 | `ReadDataB` = Rs（写数据，ALU 不用） | PASS.A | = 地址寄存器值 |
| `OUT Rs1` | 0 | `ReadDataA` = Rs1 | - | PASS.A | = 显示值 |

写回 mux 只需 2 路（ALU 结果 / RAM 读值），无需专用立即数通路。

### 3.5 `CWrite` 生成式

```
CWrite = (op == 0000 || op == 0001) && !fn[3] && !fn[2]
```

即只有 ADD/ADC/SUB/SBC 写 C（`fn[3:2]=00` 正好覆盖 `0000`-`0011`），AND/OR/XOR、`MOV`（PASS.A）、`LDI`（PASS.B）都不写。

- 必须与 `op ∈ {0000, 0001}` 相与：`fn` 槽 `[19:16]` 在每条指令里都存在，只是非 ALU 指令把它编码成 0。少了这个门，`LDA`/`STA`/`LD`/`ST`/`BZ`/`BNZ`/`JMP`/`OUT`/`HLT` 这九条的 `fn[3:0] = 0000` 会被当成 `ADD`，统统误写 C。
- `!fn[3] && !fn[2]` 恰好框住 ADD/ADC/SUB/SBC：`fn[3]=0` 排除 `1000`-`1111`（含 `PASS.B`），`fn[2]=0` 再排除 `0100`-`0111`（AND/OR/XOR 与 `PASS.A`）。剩下的就是 `0000`-`0011` 四条。
- 搬运类不需要任何手工特判：它们的 `op` 不在 `{0000, 0001}` 里，生成式自动排除在外，不必再单独提醒"它不运算、但别写 C"。

`CWrite` 与 `ALUop` 是两个独立信号——前者说"结果要不要进 C"，后者说"ALU 这一拍干什么"。它在 ID 段组合生成，但必须随 ID/EX 锁存（§2.7）、并被气泡清零（§5.2 末）。

### 3.6 存储器地址与写数据通路

MEM 级 `RAM.Address` 统一取 `EX/MEM.ALUResult`，因此存储器指令的地址在 EX 由 ALU 产生：

- `LDA`/`STA`（绝对地址）：`BSrc=1` 把 `Imm` 送上 B，`PASS.B` → `ALUResult = addr`。
- `LD`/`ST`（寄存器间接）：地址寄存器在 `[11:8]`，经读口 A 直连进 `ALU.A`，`PASS.A` → `ALUResult = 地址`。
- 写数据在 EX 段从两个前递 mux 的输出里二选一：

```
WriteData = (MemWrite && BSrc) ? A_mux_out : B_mux_out     ; → EX/MEM.WriteData → RAM.DataIn
```

选择端 `MemWrite && BSrc` 恰好只在 `STA` 上为 1（`MemWrite = op3|op5`、`BSrc = op1|op2|op3`，两者相与只剩 `op3`）——因为 `STA` 的数据源在 A 口（`[11:8]`）、`ST` 的在 B 口（`[7:4]`）。它不需要新的流水线位：`MemWrite` 与 `BSrc` 本来就在 `ID/EX` 里、本来就在 EX 段消费。

地址与写数据是两条独立通路，这正是 `ST` 能同时"算地址"和"送数据"的原因。两条路在 `EX/MEM` 会合，那里正好有两个 8 位字段各接住一个值：

| 指令 | 地址走哪条路 | 数据走哪条路 |
|---|---|---|
| `STA Rs,addr` | `Imm` → `ALU.B`（BSrc=1）→ `PASS.B` → `ALUResult` | A 口（`[11:8]` = Rs）→ A 前递 → `A_mux_out` → `WriteData` |
| `ST Rs,[Rs1]` | A 口（`[11:8]` = Rs1）→ `ALU.A` → `PASS.A` → `ALUResult` | B 口（`[7:4]` = Rs）→ B 前递 → `B_mux_out` → `WriteData` |

`ALUResult` 装地址、`WriteData` 装数据 → MEM 段分别送到 `RAM.Address` 与 `RAM.DataIn`。只有地址那一路参与产生 `ALUResult`；数据那一路是从 `A_mux_out` / `B_mux_out` 上分叉出来的（那个二选一 mux 就画在 ALU 输入旁边，取的是同一份前递结果），`STA` 的数据虽然同时挂在 `ALU.A` 上，但 `ALUop=PASS.B` 让它对结果毫无影响（§3.3）。

### 3.7 `OUT` 的数据通路

显示值必须经 ALU 到 WB：§2.7 的 MEM/WB 字段只有 `MemData[7:0]` 与 `ALUResult[7:0]`，没有 WriteData 通路；而 `OUT` 的 `MemRead=0` 使 `MemData` 等于 RAM 在该地址上的无效值。所以显示值只能取 `ALUResult`。

接法：源寄存器在 `[11:8]`（§3.2 的 A 口）→ `ReadDataA` → A 前递 mux → `ALU.A`；`BSrc=0`、`ALUop=PASS.A` → `ALUResult = Rs1` → 随 EX/MEM → MEM/WB 到 WB，由 `OutEn` 写 Output 寄存器。

### 3.8 译码器怎么搭（控制单元，ID 段）

译码器的输入就是 IR（指令寄存器）的 24 位——本设计里 IR 没有独立元件，它就是 `IF/ID` 那个寄存器（§2.7）。把整条 `Inst[23:0]` 接到译码器的输入脚上，完全正确。

但这 24 位里只有 8 位会碰到控制逻辑：`Inst[23:20]`（op）和 `Inst[19:16]`（fn）。12 个控制信号没有一个看 `rd` / `rs1` / `rs2` / `imm`——它们不在译码器里用，而是各有各的通路：

| `Inst` 位段 | 去哪儿 |
|---|---|
| `[23:20]` op | 译码器（4→16 译码器） |
| `[19:16]` fn | 译码器（`ALUop` 的 mux、`CWrite` 的与门） |
| `[15:12]` | 只写不读：不进任何读口，只锁存成 `ID/EX.rd`，再一路传到 `MEM/WB.rd` 作写地址（§2.1） |
| `[11:8]` | 寄存器堆 A 口地址；另锁存成 `ID/EX.rsA` |
| `[7:4]` | 寄存器堆 B 口地址；另锁存成 `ID/EX.rsB` |
| `[3:0]` | 保留（`op=0000` 时恒 0，其余是 `imm[3:0]`），译码器不看 |
| `[7:0]` | `ID/EX.Imm[7:0]` → `ALU.B`（§3.3） |

位序本身为什么这么排（`op`/`fn` 为什么占最高位、`fn` 为什么不在低位），见 `isa.md` §4「字段为什么这样排」。

一条 24 位的 `Inst` 扇出给这么多个取用方，是正常的总线扇出，IR 始终只有一份。所谓"只看 8 位"说的是"有几根线最终碰到了控制逻辑的门"，不等于译码器只收 8 位。

画法：一片 4→16 译码器加一层或门。Logisim 的 `Decoder` 元件（`Select Bits = 4`、`Enable` 接常量 1）输入 op，得到 16 根 one-hot 线 `op0`-`op15`（`opN` 在 `op == N` 时为 1）。每根线对应哪条指令、这根线为 1 时打开哪些信号，见 `isa.md` §8 的转置表。

接法就是把那张表的一整列或起来——一个门一个信号：

| 控制信号 | 接法 | 门 |
|---|---|---|
| RegWrite | `op0 \| op1 \| op2 \| op4` | 4 输入 OR |
| MemRead | `op2 \| op4` | 2 输入 OR |
| MemToReg | 同上，与 MemRead 共用同一条线 | - |
| MemWrite | `op3 \| op5` | 2 输入 OR |
| BSrc | `op1 \| op2 \| op3` | 3 输入 OR |
| BranchZ | `op6` | 直连 |
| BranchNZ | `op7` | 直连 |
| Jump | `op8` | 直连 |
| OutEn | `op9` | 直连 |
| Halt | `op10` | 直连 |
| CWrite | `(op0 \| op1) & !fn[3] & !fn[2]` | 1 个 OR + 1 个 3 输入 AND（§3.5） |
| ALUop[3:0] | `(op0\|op1) ? fn : ((op2\|op3) ? 4'b1000 : 4'b0111)` | 2 个 4 位 2 选 1 mux，选通信号是 `op0\|op1` 与 `op2\|op3` 两个或门 |

一共 1 片译码器 + 6 个或门 + 1 个与门 + 2 个 mux。6 个或门 = `RegWrite`、`MemRead`、`MemWrite`、`BSrc`、`op0|op1`（`CWrite` 与 `ALUop` 共用这一个）、`op2|op3`（`ALUop` 第一级选通）。`op2|op3` 不能省也不能复用别的：`MemRead` 是 `op2|op4`、`MemWrite` 是 `op3|op5`、`BSrc` 是 `op1|op2|op3`，都换不出它来。

两条让电路更简单的性质：

- `ALUop` 不必逐条指令去挑：先按 `op2|op3` 在 `PASS.B` / `PASS.A` 之间二选一，再按 `op0|op1` 在"上一步的结果"与 `fn` 之间二选一，两级就够。`BZ`/`BNZ`/`JMP`/`HLT` 谁都不选它，落到 `PASS.A`——给什么都不影响结果（这几条的 `RegWrite` / `MemWrite` / `OutEn` 全是 0，`ALUResult` 流到哪儿都没人接）。
  但不能把 `ALUop` 直接接 `fn` 了事：`LDI`/`LDA`/`STA`/`LD`/`ST`/`OUT` 的 `fn` 槽都是保留的 0，直接接过去，它们的 `ALUop` 就变成 `0000`——只有这样接错时，这些指令才是在算加法；按上式接，它们的 `ALUop` 是生成出来的常量 `PASS.B`/`PASS.A`，与 `fn` 填什么无关。接错的后果是写回或送出的变成"某个操作数加 0"而不是地址或源寄存器值。这级 mux 是必需的。
- `MemRead` 与 `MemToReg` 恒等（只有 `LDA` / `LD` 为 1），一个门扇出两根线即可。

保留 op（1011-1111）译出的 `op11`-`op15` 一根都不接，自然全 0，等效无操作。它和"全 0 指令字"是两条不同的东西：保留 op 才是真 NOP（控制位全 0），而 `op=0000 fn=0000` 是 `ADD R0,R0,R0`、会写 R0 和 C（`isa.md` §10）——分支 flush 要灌进 `IF/ID` 的是前者（§6）。将来真把这几个码用掉时（比如移位族占了某个保留 op），§6 那个 flush 常量要跟着换，它必须始终落在一个控制位全 0 的码上。

`Halt` 在这里只是译码出来的一位，别就地拿去停时钟：它要随 ID/EX → EX/MEM → MEM/WB 锁存到 WB 段才取用（§1 / §2.7）。同理 `OutEn`、`RegWrite` 这些也要一路传下去。

搭的顺序：§8 第 4 步（单周期核心）。先接 `op` → 4→16 译码器，拿到 `op0`-`op15`；再按上表逐根接到门（`BranchZ`/`BranchNZ`/`Jump`/`OutEn`/`Halt` 五根直连，不过门）；最后接 `CWrite` 的与门与 `ALUop` 的两个 mux。此时控制信号不锁存、直接从 `Inst` 组合出来——第 5 步加了流水线寄存器，才改成逐级锁存（§2.7）。

译码器里没有读口地址 mux：两个读口的地址硬接在 `Inst[11:8]` / `[7:4]` 上（§3.2 / §3.3），`op0`-`op15` 一根都不去选它们。这一片只吐 12 个控制信号，别的什么都不管。

## 4. 前递（Forwarding Unit，EX 段）

前递发生在流水线寄存器之后，不回写任何寄存器。`ID/EX` 里存的永远是寄存器堆的原始读数（`ReadDataA/B`），两个 mux 坐在"寄存器输出 → ALU 输入"这段纯组合路径上，命中时当拍现选。这在时序上不额外花钱：前递源 `EX/MEM.ALUResult` 与 `MEM/WB` 写回值都是前几拍锁存下来的寄存器输出，读 Rd 的那条这一拍一开始就是稳定值，不必去够同一个周期里正在算的 ALU 输出。

反过来做（在压进 `ID/EX` 之前就把值换掉）要付两笔账：① k=1 时写 Rd 的那条在 EX、读 Rd 的那条在 ID，是同一个周期——要提前换，就得把本周期正在算的 ALU 输出接回 `ID/EX` 的 D 端，于是每一条指令的建立时间都被加上一级 ALU，而不只是有依赖的那几条；② 靠"提前写回寄存器堆"绕也不行，写口只有一个、WB 段正占着。分支的 k=1 只能停（§4.2）正是这条的推论：那一拍结果还没落进任何寄存器，停完才在 `EX/MEM` 里成为一个干净的寄存器源（§5.1）。

EX 段有两个 3 选 1 前递 mux，选择逻辑完全相同，只是被比较的源寄存器和目的地不同：

| mux | 被比较的源 `src` | 优先级 3 的取值 | 目的地 |
|---|---|---|---|
| A | `ID/EX.rsA`（=`Inst[11:8]`） | `ID/EX.ReadDataA` | ALU 的 A 输入（直连，后面没有别的 mux）；另分叉一路给写数据二选一（§3.6，仅 `STA` 取用） |
| B | `ID/EX.rsB`（=`Inst[7:4]`） | `ID/EX.ReadDataB` | ALU 的 B 输入（后面还有 BSrc mux）；另分叉一路给写数据二选一（§3.6，仅 `ST` 取用） |

源的对应关系：A 取 `[11:8]`、B 取 `[7:4]`。只有两个 mux，因为只有两个源槽——`[15:12]` 是只写不读的目标槽（§3.2），没有任何指令从它取操作数，自然不用给它配前递。两条 store 的数据源就住在 A/B 这两个槽里，所以它们的写数据也一并吃到了前递（§3.6 那个二选一 mux 接在 A/B 的输出上，不是接在读口原始输出上）。

两个 mux 的选择规则（`src` = 上表对应字段）：

| 优先级 | 条件 | 取值 |
|---|---|---|
| 1 | `EX/MEM.RegWrite && EX/MEM.rd == src && !EX/MEM.MemRead` | `EX/MEM.ALUResult` |
| 2 | `MEM/WB.RegWrite && MEM/WB.rd == src` | WB 写回值 = `MemToReg ? MemData : ALUResult` |
| 3 | 否则 | 见上表（各 mux 不同） |

优先级 1 必须压过 2：读 Rd 的那条在 EX 那一拍，`EX/MEM` 装的是 i-1、`MEM/WB` 装的是 i-2。连续两条指令写同一个 `Rd` 时两个条件会同时命中——近的那条（i-1）必须赢，否则取到的是上上条的结果。搭反的症状：`LDI R1,9; ADD R1,R1,R1; OUT R1` 显示 `9` 而不是 `18`（§9 第 5 条）。

判据是 `RegWrite`，不是"`rd` 是不是 0"：R0 是普通寄存器，`rd=0` 也可能是真的写 R0。写 R0 的指令也必须能把值前递出去——否则 `LDI R0,#5` 紧跟一条读 R0 的指令就会拿到旧值。两个 mux 与 §5.2 的 `dep` 一律改用 `RegWrite`。

- 优先级 1 / 2 两个 mux 取的是同一个值：都是"前一条指令的 ALU 结果"。不要因为另一条路叫"写数据"就去取 `EX/MEM.WriteData`——那个字段是前一条指令自己要写进 RAM 的数据，不是它的运算结果，跟当前指令无关。
- 优先级 1 排除 MemRead：load 的结果要到 MEM 之后才在 MEM/WB 可用，`EX/MEM.ALUResult` 是地址不是数据，故 load 只从 MEM/WB 前递（配合 load-use 停顿）。
- store 的写数据不需要自己的前递 mux：它取自 `A_mux_out` / `B_mux_out`（§3.6），store 要前递的那一份本来就在这两个 mux 的射程内——它们的比较字段 `[11:8]` / `[7:4]` 正是 store 数据源住的地方（§3.2）：

  ```
          ADD R2, R3, R4
          ST  R2, [R1]      ; 数据源 R2 在 [7:4]，B 前递当拍就把它换成 R3+R4
          LD  R5, [R1]      ; 应当读回 R3+R4
  ```

  若 B 前递接错、或写数据二选一取错了口（`ST` 也去取 A），RAM 里留下的就是旧 R2——症状与判据见 §9 第 3 条（`LD` 读回 `7` 而不是 `14`）。注意它只影响写 RAM 那一路，寄存器堆里没错，单看寄存器会以为一切正常。

### 4.1 ID 段读口的时序缺口：间隔 3 条的 RAW

上面两个前递 mux 全在 EX 段，只能覆盖"写 Rd 的那条与读 Rd 的那条相隔 1 条或 2 条"的情形。相隔正好 3 条时两个前递源都够不着：

| 相隔 k | 读 Rd 的那条进 EX 时，写 Rd 的那条在 | 覆盖手段 |
|---|---|---|
| 1 | EX/MEM | A/B 前递（优先级 1） |
| 2 | MEM/WB | A/B 前递（优先级 2） |
| 3 | 已流出流水线 | 无，只能指望寄存器堆 |
| ≥4 | 已流出 | 寄存器堆（写入早已生效） |

k=3 是最坏的一种：读 Rd 的那条在 ID 读寄存器堆时写 Rd 的那条还没写回，等读 Rd 的那条进 EX 时写 Rd 的那条又已经排空了。失败实例（`LDI` 写 R1，隔 2 条指令后用 R1 做地址）：

```
00  LDI R1, 0x10
01  LDI R2, 5
02  LDI R3, 3
03  LD  R4, [R1]     ; ← 00 与 03 相隔 k=3
```

| 拍 | ID | EX | MEM | WB | 现象 |
|---|---|---|---|---|---|
| T5 | 03 | 02 | 01 | 00 | ID 读 R1 得 0x00（00 的写回在本拍末沿才生效） |
| T6 | 04 | 03 | 02 | 01 | A mux 优先级 1 是 02(rd=R3)、优先级 2 是 01(rd=R2)，都不是 00 |

结果 `ALU.A = 0` → `LD` 读的是 `RAM[0]` 而不是 `RAM[0x10]`。这不是 load 独有：`ADD R4,R1,R1`、`ST R2,[R1]`、`BZ R1,addr` 等任何在 k=3 位置用 R1 的指令都一样错。

修法（二选一，推荐第 1 种）：

1. 寄存器堆改用下降沿写（推荐）。只动 §2.1 那一个模块：直接把 16 个 `Register` 的 `Trigger` 设成 `Falling edge`。这样在同一拍内，WB 的写发生在前半拍、ID 的读在后半拍看到新值，而 `ID/EX` 要到本拍末的上升沿才锁存——锁存到的就是新值。零额外比较器/选择器，也顺带修好 §5 分支判零的同类问题（`BZ`/`BNZ` 的判零 NOR 同样在 ID，同样吃 k=3）。
2. 加一路 WB→ID 前递。在 ID 的两个读口后各加一个 2 选 1 mux，比较 `MEM/WB.rd` 与两个读口地址，命中则取 WB 写回值。开销 2 个比较器 + 2 个 mux，好处是保住"全设计单一时钟相位"。
   - 这条只修寄存器堆读口的 k=3，救不了分支。分支在 ID 判零，它额外需要 `EX/MEM` 那个源（k=2），见 §5.1。只按本项搭、完全不管分支的话，`examples/hazard_branch.asm` 照样失败。

改完后的覆盖情况（仅限"在 EX 段用操作数"的指令）：k=1/2 归 EX 的两段前递，k=3 归这次的修改，k≥4 寄存器堆里早已是新值。`BZ`/`BNZ` 不在其列——它们在 ID 判零，取值的时刻比别的指令早一级，另需一套 ID 段前递加额外停顿规则（§5.1 / §5.2）。完整对照见 §4.2。

可直接加载运行的自测程序见 `examples/hazard_k3.asm`（`build/hazard_k3.mem`）——调试项 §9 第 8 条：应输出 `0xFF`，写口用了上升沿时输出 `0x00`。`0x00` 有两种成因（写口没改下降沿，或 load-use 没停），见 `README.md` 的判据表；看到它时两项都要查。

### 4.2 依赖距离 → 解决手段（权威总表）

写 Rd 的那条在前、读 Rd 的那条在后，`k` = 运行时两者相隔几级流水线（中间没有插进停顿时就等于两条指令的序号之差：`k = i(读 Rd 的那条) - i(写 Rd 的那条)`）。读 Rd 的那条在流水线的哪一段用这个值，决定了它需要哪条通路——这是全文档最容易记错的一点，因为同一个 `k` 对不同指令类型意味着不同的硬件。

"在 EX 段用"指的是这个值被取用的位置，不是寄存器堆被读的位置。两个读口都在 ID 段读（地址直接就是 `Inst` 的两个字段，§2.1），读到的数随 `ID/EX` 锁存下去；到 EX 时若它已经过时，由前递 mux 当场换掉。读在 ID、用在 EX，两件事分属两段——前递之所以接在 EX，正是因为效期是在那里判的。`BZ`/`BNZ` 是唯一两件事都落在 ID 的（判零 NOR 就在 ID），所以它单列一行。

| 读 Rd 的那条（在哪一段用值） | k=1 | k=2 | k=3 | k≥4 |
|---|---|---|---|---|
| 在 EX 段用：ALU 族（`LDI` / `LDA` 除外）/ LD / ST / STA / OUT | A/B 前递，源 `EX/MEM`（§4） | A/B 前递，源 `MEM/WB`（§4） | 寄存器堆下降沿写（§4.1） | 寄存器堆 |
| 在 EX 段用，且写 Rd 的那条是 load | 停顿 1 拍，之后从 `MEM/WB` 前递（§5.2 ①） | A/B 前递，源 `MEM/WB`（§4） | 寄存器堆下降沿写（§4.1） | 寄存器堆 |
| 在 ID 段用：BZ / BNZ（判零） | 停顿 1 拍，之后从 `EX/MEM` 前递（§5.2 ②） | `EX/MEM` → ID 前递，不停顿（§5.1） | `MEM/WB` → ID 前递，或下降沿写口（§5.1） | 寄存器堆 |
| 在 ID 段用，且写 Rd 的那条是 load | 停顿 2 拍，之后从 `MEM/WB` 前递（§5.2 ③） | 停顿 1 拍，之后从 `MEM/WB` 前递（§5.2 ③） | 不停顿（§5.1） | 寄存器堆 |

"写 Rd 的那条"一律指 `RegWrite=1` 且写的是 Rd（R0 是普通寄存器，没有 `rd≠0` 这个等价说法）。

两条"且写 Rd 的那条是 load"的行说的是同一件事：load 的值要等它自己走完 MEM 段才可用，比别的指令晚一级。所以每格只需比它上面那行多等一拍——EX 行的 k=1 从"前递"变成"停 1 拍"（停完就落进同一行 k=2 那格的 `MEM/WB` 通路），ID 行的 k=1 由 1 拍变 2 拍、k=2 由不停变停 1 拍。判据：EX 行用 `examples/square_lookup.asm`（§9 第 6 条，load-use 的首选判据；`hazard_k3.asm` 的 `0x00` 也验这一项，但那个值还有第二种成因），ID 行用 `examples/hazard_loadbranch.asm`（§9 第 13 条）。

`LDI` 与 `LDA` 不在"在 EX 段用"那两行里：两条都是 `BSrc=1` → `PASS.B`（`Result ← B`，§3.4），A 口那份读数根本不参与运算——`LDA` 的操作数是立即数 `addr[7:0]`、`LDI` 的是 `imm[7:0]`，两条都一个寄存器都不读，所以永远当不了读 Rd 的那条，只可能当写 Rd 的那条。`STA` 反过来在列——它的数据源在 `[11:8]`，走 A 前递（§3.2 那张表）。

为什么两条 ID 行与两条 EX 行不同：读 Rd 的那条在 ID 的那一拍，`ID/EX` 装的是 i-1（还在 EX，结果尚未产生）、`EX/MEM` 装的是 i-2、`MEM/WB` 装的是 i-3。所以分支的 k=1 只能靠停，k=2 必须从 `EX/MEM` 取——这与 EX 段那两个 A/B mux 的源不是同一组，另需一套独立的 mux。

> 上表的 `k` 是运行时两条指令相隔几级流水线，不是源码里数出来的条数。一条插进去的停顿会把后面所有读 Rd 的那条的有效距离推大——写 Rd 的那条在停顿后继续前进，而它后面的读 Rd 的那条在 IF/ID 里被冻住。于是"静态 k=2"可能变成"运行时 k=3"。**丢一拍的不止停顿：taken 分支在 ID 解决时会 flush 掉已取的那条（§6），每跳一次同样丢 1 拍，算 `k` 时也要算进去**——只数停顿会系统性低估 1（`sum1to10.asm` 的循环体每轮就是"1 拍停顿 + 1 拍 flush"，两处静态相隔 3 条的源寄存器实际都是 k=4）。
> 实例：`examples/hazard_branch.asm` 的 `MOV R3,R2`(02) → `BZ R3,wrong`(03) → `OUT R3`(04)。数条数是 k=2，但 03 触发的那 1 拍停顿让 04 在 ID 读口时 `MOV R3` 正好在 WB——它实际吃的是 k=3 的下降沿写口（判据：把写口改回上升沿，它输出 `0x00` 而非 `5`）。详见 §9 第 9 条。
> 所以验收要以"去掉某项修复程序会不会错"为准，而不是以"静态数出几处冒险"为准；`README.md` 有一张按这个标准列的判据表。

三处易错点（症状见 §9 第 11-13 条）：

1. ID 前递只搭 `MEM/WB` 一路 → k=2 的分支读到旧值。
2. 停顿期间不封 `branch_taken` → 停顿拍上那个"用旧值算出来"的分支结论会去 flush，把正在停顿的分支自己冲掉。
3. 分支源来自 load 时只停 1 拍 → load 在 MEM 段时 `EX/MEM` 里只有地址、没有数据，1 拍不够。

## 5. 冒险检测（Hazard Unit，ID 段）

本段共三件事：① 分支判零的取值网络、② 停顿的产生条件、③ 停顿期间必须封锁的输出。三者的关系是"①决定能拿到什么值，②决定拿不到时怎么等，③决定等的这一拍不能顺手做错事"。

产出的四个控制信号：`PCWrite`、`IF_IDWrite`、`ID/EX 清零`、`IF_ID flush`。汇总见 §6。

### 5.1 分支判零：ID 段前递网络

判零 NOR 放在 ID 段：接在分支操作数（前递后）的取值线上 → 输出 1 位 `Zero` → 与 BranchZ/BranchNZ 合成 `branch_taken` → 驱动 PC mux。不是 ALU 自带的 Zero 输出（那是 EX 段、判 ALU 结果全 0 用的，本设计的分支用不到，可空置）。

为什么判零放在 ID 段：代价与收益都落在"跳一次作废几条"上。在 ID 判定只作废一条——PC 刚取到的那条（flush `IF/ID`）；若挪到 EX 判定，RAW 其实更好办（除 load 外，k=1/k=2 的写 Rd 的那条结果那时都已在 `EX/MEM` / `MEM/WB` 里，直接前递即可、不必停），但每条跳转要作废两条（`IF/ID` 和 `ID/EX` 都得 flush）。本设计选了前者——付一套独立的 ID 前递网络加两条停顿规则（§5.2 ②③），把跳转代价压在 1 拍。

分支操作数要一个独立的 3 选 1 mux——结构与 §4 那两个 A/B mux 相同，但源不一样（这是最容易照抄错的地方）：

```
BranchOperand = 3 选 1 mux(选择信号见下，输入 0 优先级最高)

  输入 0:  EX/MEM.ALUResult        命中条件: EX/MEM.RegWrite && !EX/MEM.MemRead
                                              && EX/MEM.rd == src
  输入 1:  MEM/WB 写回值            命中条件: MEM/WB.RegWrite && MEM/WB.rd == src
          (= MemToReg ? MemData : ALUResult)
  输入 2:  寄存器堆 A 口输出         否则

  src     = Inst[11:8]   ; BZ/BNZ 的判零源就在普通的 rs1 槽，见 isa.md §4
  Zero    = (BranchOperand == 0)     ; ← 8 输入 NOR（或 = 常量 0 比较器）放这里
  branch_taken = ((BranchZ && Zero) || (BranchNZ && !Zero)) && !stall
```

- 输入 0（`EX/MEM`）不能省，且优先级必须高于输入 1。读 Rd 的那条在 ID 的那一拍：`EX/MEM` 装的是 i-2、`MEM/WB` 装的是 i-3。所以 k=2 的分支只有 `EX/MEM` 这一路够得着——只做 §4.1 修法 2 那种"`MEM/WB`→ID"的单路前递，`examples/hazard_branch.asm` 会失败（症状见 §9 第 9 条）。`!EX/MEM.MemRead` 的含意与 §4 完全一致：load 在 MEM 段时 `EX/MEM.ALUResult` 是访存地址不是数据，不能当结果前递出去。k=3 由输入 1 或 §4.1 的下降沿写口覆盖（两条任取其一即可）；k≥4 寄存器堆里已是新值。完整对照见 §4.2。
- 取值口固定是 A 口（`[11:8]`），无需 opcode mux——见 §3.2。判零源就住在正常的 `rs1` 槽里，没有借用别的字段。
- 命中：`IF/ID flush=1`（本周期取入的指令作废），`PCNext = Inst[7:0]`。
- `Jump` 时 `PCNext = Inst[7:0]` 且 flush。

`branch_taken` 与 `IF_ID flush` 必须被 `!stall` 封住（极易漏）：一个正在停顿的分支同一拍仍在 ID 上做判定，而它这一拍读到的值，正是"这次停顿要解决的那个旧值"。若让这个结论去驱动 flush，它会把正在停顿的分支自己冲掉；PC 又因 `PCWrite=0` 而没跳——分支就此消失，永远没有第二次机会。

失败实例（完整程序见 §9 第 12 条）：先把 R3 预置成非 0（`LDI R3,9`），再让 `MOV R3,R2` 紧跟 `BNZ R3,tgt`。停顿拍上读到的是旧 R3=9（≠0，看着"该跳"），于是 flush 掉 BNZ；正确结果是跳到 `tgt` 打印 `0x07`，实际打印了顺落的 `0x10`。

这个 bug 只在"停顿拍上的旧值与停顿后的新值判出同一个'跳'"时才看得见。旧值判"不跳"时 `branch_taken=0`，压根不产生 flush，下一拍用前递来的新值重判，结果完全正确；旧值判"跳"、新值判"不跳"时，那条分支确实被误 flush 掉了，但顺落下去的路径恰好就是正解路径——`examples/hazard_branch.asm` 正属这一种（旧 R3=0 让 `BZ` 判"跳"、`BZ` 真把自己冲掉了，可"不跳"该走的也是同一条 `OUT R3`，输出仍是 `5`），所以它是这条修复的假通过；而 `fib` / `sum1to10` / `array_sum` 的循环每轮新旧值都判"跳"，一抓就中。

### 5.2 停顿（stall）的三条来源

```
stall = ① ID/EX 是 load，且它写的寄存器是读 Rd 的那条的任一字段   ; 经典 load-use（写 Rd 的那条在 i-1）
     || ② 读 Rd 的那条是 BZ/BNZ，且写 Rd 的那条在 i-1             ; 分支源由"紧邻前一条"产生
     || ③ 读 Rd 的那条是 BZ/BNZ，且源被在飞的 load 生产          ; 分支源来自 load：k=1 停 2 拍、k=2 停 1 拍
```

接成线（三段条件都要）。`Inst[...]` 指 IF/ID 中当前那条指令的字段：

```
dep        = ID_EX.RegWrite && ( ID_EX.rd == Inst[11:8]
                             || ID_EX.rd == Inst[7:4] )

load_dep   = (ID_EX.MemRead && dep)                                     ; ①
           || (IF/ID 是 BZ/BNZ                                          ; ③ k=1
               && ( (ID_EX.MemRead && ID_EX.RegWrite && ID_EX.rd == Inst[11:8])
                 || (EX/MEM.MemRead && EX/MEM.RegWrite                  ; ③ k=2
                     && EX/MEM.rd == Inst[11:8]) ))

branch_dep = (IF/ID 是 BZ/BNZ) && ID_EX.RegWrite && ID_EX.rd == Inst[11:8]  ; ②

stall      = load_dep || branch_dep
```

两个字段就是两个读口的地址（§3.2），直接比较，不需要任何中间量。"写 Rd 的那条"一律用 `ID_EX.RegWrite` / `EX/MEM.RegWrite` 判定——`rd` 每条指令都编码得出一个有意义的值，不能拿它当"不写"的标记。

③ 的 k=2 那半比的是 `EX/MEM.rd`，不是 `ID_EX.rd`——那一拍 load 已经走到 `EX/MEM`，`ID_EX` 装的是更前一条。这次相等比较与 §5.1 输入 0 是同一个（都是 `EX/MEM.rd == Inst[11:8]`，也都带 `EX/MEM.RegWrite`），只差 `MemRead` 的正反门：输入 0 要 `!MemRead`（load 的 `ALUResult` 是地址），③ 要 `MemRead`（正是在飞的那个 load）。两处都在 ID 段，接线时共用一个比较器再分两个门即可，不必搭两遍。三套网络（§4 的两个前递 mux / §5.1 的分支 mux / 本节这个）各自的比较字段对照见 `isa.md` §9。

① 为什么只能停、不能靠前递：load 的数据要到它自己走完 MEM 段才落进 `MEM/WB`（`EX/MEM.ALUResult` 是地址）。读 Rd 的那条在 EX 那一拍，写 Rd 的那条（这里是 load）刚走到 `EX/MEM`——优先级 1 被 `!EX/MEM.MemRead` 排除，优先级 2 的 `MEM/WB` 里装的还是更早的 i-2，两个源都够不着。停 1 拍后 load 进 `MEM/WB`，值就前递得过来了。症状见 §9 第 6 条；内置判据是 `examples/square_lookup.asm`（应输出 `9`，漏插气泡得 `0`）——load-use 的首选判据。`hazard_k3.asm` 的 `LDA R4,0x10` → `OUT R4` 同样考这一项，但它的 `0x00` 与 k=3 没修好同值，两种成因要一起查。

"停 1 拍"具体停掉了什么（以 `square_lookup.asm` 的 `LD R5,[R4]` → `OUT R5` 为例，`OUT` 的源在 A 口）：

| 拍 | ID | EX | MEM | WB | 这一拍 |
|---|---|---|---|---|---|
| T2 | OUT | LD | 前一条 | 更早 | `ID_EX` 装着 LD（`MemRead=1`），`ID_EX.rd`=R5 命中 `OUT` 的 `[11:8]` → `stall=1` |
| T3 | OUT（原地等） | 气泡 | LD | 前一条 | `ID_EX` 已清成气泡 → `dep=0`，停顿解除；LD 不受影响，照常前进 |
| T4 | 后续 | OUT | 气泡 | LD | 优先级 1 是气泡、不命中；优先级 2 命中 `MEM/WB` 里的 LD → 拿到 `MemData` |

停顿不是"全线冻结"，是"冻两头、清中间"（§6）：`PCWrite=0` 冻 PC、`IF_IDWrite=0` 冻 `IF/ID`——所以读 Rd 的那条不会消失，它停在 ID 原地等、下一拍把寄存器堆重读一遍；唯独 `ID/EX` 是被改写、不是被保持，气泡就是从这儿来的。清 `ID/EX` 也伤不到写 Rd 的那条：末沿写它影响的是下一拍的 EX 段，而占用 EX 的 LD 在拍末已经带着结果进了 `EX/MEM`。于是读 Rd 的那条晚一拍进 EX、写 Rd 的那条按时进 `MEM/WB`——静态的 k=1 在运行时变成 k=2，正好落进优先级 2 的射程。这也说明为什么 `EX/MEM` 那级救不了 load：T3 时 LD 在 `EX/MEM`，但里面装的是地址；`MemData` 要等它进 `MEM/WB`、由 `MemToReg` 选出来才可用。

② 为什么不能带 `ID_EX.MemRead`：判零 NOR 在 ID，要的是已经算出来的值。写 Rd 的那条正在 EX 时（`ID/EX` 里装的就是它），此刻结果尚不存在——`EX/MEM` 装的是再前一条、`MEM/WB` 更前，两个 ID 前递源都够不着。所以读 Rd 的那条是分支时，无论写 Rd 的那条是什么类型都得停。失败实例：`ADD R2,R2,R1` 紧跟 `BZ R2,target`——`BZ` 会按旧 R2 判定。注意这与 §4.1 的 k=3 是两回事：k=3 是"写 Rd 的那条已流出流水线、两个前递源都空了"；这里是"写 Rd 的那条还在 EX、结果尚未产生"。前者靠改读取时序或加 ID 前递，后者只能靠停。

③ 为什么必须单独列（程序见 `examples/hazard_loadbranch.asm`，逐条说明见 §9 第 13 条）：②只挡得住"写 Rd 的那条在 i-1"的那一拍。可当写 Rd 的那条是 load 时，停 1 拍后 load 只是从 EX 走到 MEM——MEM 段的 `EX/MEM` 里只有地址、没有数据（数据要等它进 `MEM/WB`）。而那一拍 `ID_EX` 已换成气泡（`RegWrite=0`），②的条件自动变假，分支就带着旧值判定了。正确的判据是"分支的源还被关在某个在飞的 load 里"，效果是 k=1 停 2 拍、k=2 停 1 拍、k=3 不用停（与 §4.2 表一致）：

- k=1：load 在 `ID/EX` → 停；下一拍 load 到 `EX/MEM` → 再停；第三拍进 `MEM/WB`，可前递。
- k=2：load 已在 `EX/MEM` → 停 1 拍；下一拍进 `MEM/WB`，可前递。
- k=3：load 已在 `MEM/WB`，数据就在眼前，直接前递，不用停。

前提是气泡要清 `RegWrite`（见本节末 stall=1 的说明），否则 ② 会在气泡上误触发。③ 的示例是 `examples/hazard_loadbranch.asm`。不要拿 `array_sum.asm` 的第 0E 条当它——那条是普通的 load-use（`LD R5,[R1]` 紧接 `ADD R2,R2,R5`），不是分支。

> 误停无害，且不要为它加特判：`dep` 比较的两个源槽里没有一格是"永远为源"的——`[11:8]` 在 `LDI`/`LDA`/`JMP`/`HLT` 里按约定编 0（读到 R0，没人消费），`LD R0,[R1]` 紧跟 `LDI R1,#5` 就会让这条 `LDI` 多停 1 拍；`[7:4]` 在立即数型与 `LDI`/`LDA` 里是立即数/地址的位，`LDI R1,0x30` 的 `[7:4]` 是 3，紧跟一条**写 R3 的 load** 就多停 1 拍。这些槽位上装着的非源值（立即数位、地址位、按约定编的 0）都可能正好等于某个写 Rd 的那条的 `rd`，于是出现"读 Rd 的那条其实不读这个寄存器，却被判定为依赖"的假命中：
> ```
>         LD  R0, [R2]      ; 写 R0、读 R2
>         LDI R1, 0x50      ; 不读任何寄存器；它的 [11:8] 按约定编 0，正好等于 LD 的 rd
>                           ; → 多停 1 拍
> ```
> 假命中的本质是读 Rd 的那条在那一格上根本不是源：`LDI` 不读任何寄存器，`[11:8]` 里的 0 只是一个编码约定。它跟"两条写的是不是同一个寄存器"无关——按架构语义这条 `LDI` 一条停顿都不需要（写是有序的，它又什么都不读）。冒险单元分辨不了，它手上只有两个裸字段值，比相等就停。
>
> 但真依赖一个都不能漏：`[11:8]` / `[7:4]` 恰好覆盖了全部源——包括两条 store 的数据源（`STA` 在 `[11:8]`、`ST` 在 `[7:4]`，§3.2）。`LD` → `ST` 的 RAW 就由 `[7:4]` 那一项接住：
> ```
>         LD  R3, [R1]      ; R3 ← 载入值
>         ST  R3, [R2]      ; 数据源 R3 编在 [7:4]，漏比这一项就漏停
> ```
> 漏停的后果是写进 RAM 的是旧 R3——`ST` 在 EX 那一拍，优先级 1 被 `!EX/MEM.MemRead` 排除、优先级 2 的 `MEM/WB` 里只有更早的指令，两个源都够不着。宁可多停，不能漏停，这也是 `dep` 逐槽盲比、不按指令类型精修的理由（见本节末）。
>
> `[15:12]` 不必比较：它对本 ISA 里任何指令都只是目标槽、永远不当源（§3.2），不可能产生真依赖；比它只会多出一类假停。**这条的前提是"源不进 `[15:12]`"**：哪天真把某个源挪回那个槽，这一项就得加回来。
>
> 它只损失周期，不损失正确性——停顿只是冻结读 Rd 的那条、放写 Rd 的那条前进，`k` 只会变大不会变小；而两个前递 mux 各自按自己的源字段比较（§4），与 `dep` 无关，不会因为这次假命中取错值。
>
> 代价有上界，而且只在 ① 那条路上：②（`branch_dep`）与 ③ 的两个条件都只比 `Inst[11:8]`，而它对 `BZ`/`BNZ` 恰好正是源字段——所以分支那条永远不会误判。真正花掉周期的唯一路径是 ①，即写 Rd 的那条是 load（`ID_EX.MemRead=1`），每次假命中多停 1 拍。
>
> 为什么不用"指令类型门"把它消掉：门本身不贵——`op0` 与 `MemWrite = op3|op5` 都已经是算好的信号，多 2 个与门；省下的正是上面那 1 拍。但 `dep` 现在是逐字段盲比，因此它是真实依赖集的超集——永不漏停。加了类型门，比较就跟着指令类型走，一处漏写就变成漏停：那是错的值，不是慢一拍。按本设计一贯的取向（宁可多停，不能漏停），这个交换不划算。
>
> 换成读口地址 mux 也绕不过去：假命中产生在比较网络（`dep` 比裸字段、§4 那两个 mux 比锁存副本），不在读口——两个口的地址线永远接着，两个字段每拍都已读出并锁进 `ID/EX`，缺的从来不是"源有没有被读到"，而是"这一格这拍算不算源"；这句话只有译码器答得上来，地址 mux 一句也不多给。同理，把寄存器号搬进非 ALU 指令空着的 `fn` 槽也没有收益：假命中来自源槽里装着的非源值，换个槽位只是把垃圾从一个被比较的格子挪到另一个被比较的格子。要精确比较，只用得上上面那两个与门。

stall=1 时：`PCWrite=0`（PC 保持）、`IF_IDWrite=0`（IF/ID 保持）、`ID/EX 控制信号清零`（插入 NOP 气泡，`RegWrite` 与 `rd` 也一并清 0）。

清零的必须是全部控制位，`CWrite` 也在内。气泡只清控制信号，ID/EX 里的 `ReadDataA/B` 仍是残留值，而 `ALUop` 被清成 `0000`（= ADD）——ALU 照样在算、`Cout` 是无效值。若 `CWrite` 是从 `ALUop` 组合译码出来的（而不是锁存的控制位），气泡就会把无效进位写进 C。见 §3.5。

`RegWrite` 必须和控制位一起清 0：上面 ①②③ 都以 `RegWrite` 为前提，气泡若留着它，下一拍会误触发停顿。（`rd` 也顺带清 0，纯粹是卫生——判定已经不看它了。）

为什么"控制位全 0"就等于 NOP：架构状态的每一处改变都由这 12 位里的某一位把门——`RegWrite` 写寄存器堆、`MemRead`/`MemWrite` 访存、`CWrite` 写 C、`OutEn` 写显示、`Halt` 停机。全 0 时一个门都不开，所以气泡不必是"一条合法指令"。照旧动作的只有 ALU（`ALUop` 被清成 `0000` = ADD，还可能吐无效进位），但它的结果没有接收方：两个前递 mux 与 §5.1 的两个 ID 前递源都以 `RegWrite` 为命中条件（§4 / §5.1），一个 `RegWrite=0` 的 `ALUResult` 谁也取不走。漏清任何一位都会破坏这个性质，最狠的是 `Halt`——气泡一路流进 `MEM/WB` 后会把 `ClockEnable` 拉低，整机冻死（§1）。

## 6. PC 与流水线控制汇总

| 控制 | 产生条件 | 作用 |
|---|---|---|
| `branch_taken` | `((BranchZ&&Zero) \|\| (BranchNZ&&!Zero)) && !stall` | 分支判定，必须带 `!stall` |
| PCNext = Inst[7:0] | `branch_taken` 或 Jump | 跳转 |
| PCNext = PC+1 | 否则 | 顺序 |
| PCWrite = 0 | stall | PC 保持 |
| IF_IDWrite = 0 | stall | IF/ID 保持（被停住的那条指令原地等） |
| IF_ID flush | `(branch_taken \|\| Jump) && !stall` | 作废取错指令：灌保留 opcode `0xF00000`（不是全 0，见下） |
| ID/EX 清零 | stall | 插气泡（`RegWrite` 一起清 0） |
| ClockEnable = 0 | `MEM/WB.Halt` | 停机：全部时序元件冻结，PC 与 OUT 保持（§1） |

两处 `!stall` 不能省（见 §5.1）：停顿拍上分支仍在 ID 判定，读到的是正要被停顿修掉的旧值。放它去 flush 就会把正在停顿的分支自己冲掉，而 `PCWrite=0` 又拦着 PC 不跳——这条分支从此消失。加 `!stall` 后它原地等，等到值前递过来再重新判定。

flush 灌进 `IF/ID` 的常量是保留 opcode `0xF00000`，不是全 0。v2 里全 0 译出来是 `ADD R0,R0,R0`（`isa.md` §10），`RegWrite` 与 `CWrite` 都是 1——每跳转一次就把 `R0 ← R0+R0`、再往 C 里写一个无效进位，程序只要用到 R0 或 `ADC`/`SBC` 就会被悄悄改坏。保留 opcode 译出的控制位全 0（§3.8），才是真 NOP。做法：`IF/ID` 的 D 端加一个 2 选 1 mux，flush 时选常量 `0xF00000`。

flush 要压过 `IF_IDWrite=0`：`IF/ID` 的写使能取 `IF_IDWrite || flush`。正确接线下两者互斥（flush 带着 `!stall`），但 §9 第 12 条要测的恰恰是"flush 漏了 `!stall`"那种接法——那一拍两根线同时有效，必须让 flush 赢。否则 `IF/ID` 原地保持，`BNZ` 下一拍用前递来的新值重判，那个 bug 就一点痕迹都不留。

## 7. 各段职责速查

各段的行为规范见 `isa.md` §7。这里只列每一段里有哪些组合逻辑要接：

| 段 | 这一段要接的东西 |
|---|---|
| IF | ROM 读（地址 = PC）、PC+1 增量器、跳转目标 mux（§2.6） |
| ID | 译码器（§3.8）；两个读口接字段（§3.2）；判零 NOR 与前递后分支 mux（§5.1）；停顿逻辑（§5.2） |
| EX | 两个前递 mux（§4）、`BSrc` mux（§3.3）、写数据二选一（§3.6）、ALU（§2.2）、C 寄存器（§2.3） |
| MEM | `RAM.Address ← EX/MEM.ALUResult`、`RAM.DataIn ← EX/MEM.WriteData`、`MemWrite` 接写使能（§3.6） |
| WB | MemToReg mux 选写回值 → 寄存器堆写口（地址取 `MEM/WB.rd`）；OutEn 写 Output 寄存器（§2.8） |

## 8. 建议搭建顺序（每步可独立验证）

1. 寄存器堆 → 用常量驱动地址，验证读写与全部 16 个寄存器。两个读口（地址 A/B 分别接 `Inst[11:8]`/`[7:4]`），写口用下降沿（R0-R15 的 `Trigger` 设成 `Falling edge`，做法与理由见 §2.1）——这是全设计唯一要动时钟的地方。
   > 为什么第 1 步就要下降沿：在这一步看不出任何好处——地址是常量，读到的永远是稳态值，用哪种沿都对。它要到第 7 步才兑现：这是给 §4.1 的 k=3 RAW 准备的。读 Rd 的那条在 ID 读口要拿到同拍 WB 正在写的值，只有当 WB 的写沿早于 ID 读口的采样时刻时才成立，而下降沿正是这一点。
   >
   > 所以往下搭时留意两处：第 6 步加前递 mux 时别觉得多此一举改回上升沿（两个前递 mux 加寄存器堆下降沿写口是一套，缺任何一个都漏 k=3）；第 7 步跑 `examples/hazard_k3.asm`（应 `0xFF`）把它钉死。
2. ALU → 逐功能码验证 `0000`-`1000`（含 SUB 借位、ADC/SBC 进位入出、`PASS.A` 把 A 原样送到 `Result`、`PASS.B` 把 B 原样送到 `Result`）。九行现成的输入/期望值见 §2.2 末的逐码验法表——拿常量喂 A / B / Cin，看 `Result` 与 `Cout` 两个 LED 即可，不需要任何程序。
3. 数据 RAM + ROM（先 Load 一个手工 hex 验证读）。
4. 单周期核心：不插流水线寄存器，把 IF/ID/EX/MEM/WB 直连，先跑通 `LDI R1,5; OUT R1; HLT`。
   - 译码器（控制单元）在这一步搭：4→16 译码器 + 6 个或门 + 1 个与门 + 2 个 mux，输入 `Inst[23:20]` 与 `Inst[19:16]`，输出 12 个控制信号——接法见 §3.8。此时控制信号不锁存，直接从 `Inst` 组合出来。
   - 这一步的 Output 寄存器（§2.8）也要搭上——没有它就没有任何东西可观察，本步与 §9 各条的验收全靠 OUT 显示。第 8 步只是给它补 `ClockEnable`；写地址在这一步也从 `Inst[15:12]` 直取（第 5 步加了流水线寄存器后要改接 `MEM/WB.rd`，见 §2.1）。
   - 这一步顺带验两个读口接对了字段：`ST`/`OUT` 各跑一遍（见 §9 第 4、5 条）。
5. 加流水线寄存器（IF/ID、ID/EX、EX/MEM、MEM/WB），此时不处理冒险。
6. 加 Forwarding Unit + 前递 mux。寄存器堆写口保持第 1 步的下降沿——mux 管 k=1/k=2、下降沿管 k=3，两者合起来才覆盖全部 RAW（见 §4.1）。
7. 加 Hazard Unit（停顿）+ 分支判零 + ID 段前递 + flush + PC 控制。这一步最容易一次踩三个坑（见 §5.1 / §5.2）：
   - 分支操作数的 3 选 1 mux 要有 `EX/MEM` 那一路，不能只做 `MEM/WB`——k=2 的分支只有前者够得着；
   - 停顿条件别只带 `ID_EX.MemRead`，且分支源来自 load 时要多停（k=1 停 2 拍、k=2 停 1 拍）；
   - `branch_taken` 和 `IF_ID flush` 都要 `&& !stall`；flush 灌进 `IF/ID` 的是保留 opcode `0xF00000`、不是全 0，且它要压过 `IF_IDWrite=0`（两条理由见 §6）。
   - 验收：`examples/hazard_k3.asm`（应 `0xFF`）、`examples/hazard_branch.asm`（应 `5`）。
8. 加 C 标志、停机使能 `ClockEnable`（§1）、复位。（Output 寄存器在第 4 步就该有了；这一步给它接上 `ClockEnable`。）

## 9. 调试要点

每条的「（§8 第 N 步）」就是它该在哪个阶段跑：搭完一步，把标着该步的条目跑一遍再往下走。

这是单向约定——§8 的每一步不一定都有条目。第 2 / 3 / 5 步（ALU、RAM+ROM、加流水线寄存器）靠直接观察就能验完（功能码逐个试一遍、Load 一个手工 hex、单步看流水线寄存器内容），没有"容易认错的失败症状"可写，就不硬凑条目。反过来，§9 的每一条都要标明它属于哪一步——只有与具体步骤无关的手法类条目（第 1、15 条）标「通用」。

1. 单步时钟（通用手法）：逐拍看 PC、各流水线寄存器、寄存器堆、LED 显示，与 `.lst` 清单对照。
2. 前递对不对（§8 第 6 步）：跑 `ADD R1,R2,R3` 紧跟 `ADD R4,R1,R5`，R4 应 = R1+R5。若错，查 Forwarding Unit 比较逻辑与 mux 选择。
3. store 的写数据吃到前递、且选对了口（§8 第 6 步；§3.6）：
   ```
           LDI R2, 7
           LDI R1, 0x20
           ADD R2, R2, R2     ; R2 = 14
           ST  R2, [R1]       ; 把 14 写进 RAM[0x20]（数据源 R2 在 [7:4]，k=1）
           LDI R5, 0          ; 填充，把 LD 与 LDI R1 拉开到 k=4
           LD  R3, [R1]       ; R3 应 = 14
   ```
   R3 应 = 14。两个错值各有各的成因：
   - 得 7 → B 前递 mux 没把 `ADD` 的结果换进来，写进 RAM 的是旧 R2；
   - 得 `0x20`（= 地址 R1 的值）→ 写数据的二选一取错了口，`ST` 也去取 A 口了（§3.6 那个 `MemWrite && BSrc`）。
   - `LDI R5, 0` 是填充，不能省，也不能挪到 `ST` 前面：本条要求 `ST` 距 `LDI R1` 是 k=2、`LD` 距 `LDI R1` 是 k≥4，插在 `ST` 后面才同时满足（插前面会把 `ST` 顶成 k=3）。少了它，`LD` 就是 k=3，本条会连带依赖 §4.1 的下降沿写口——写口坏掉时 `LD` 读到的 R1 是旧值 0，转去读 `RAM[0]`、R3 得 `0`，而这里只声明了 14 / 7 两个值。
4. 两个读口接对字段（ST —— 一条指令同时用两个口）（§8 第 4 步；§3.2）：`LDI R1,0x20; LDI R2,0x55; ST R2,[R1]; LD R3,[R1]` → R3 应 = 0x55。
   - 若 `RAM[0x20]` 没动、别处冒出 0x55 → A 口没接 `[11:8]`，地址取错了寄存器。
   - 若写进 `RAM[0x20]` 的是 0 → B 口读到的不是 `[7:4]`（`ST` 的数据源就在这一格，读错格自然读到 R0）；写进去的是 `0x20`（地址本身）→ 写数据的二选一取错了口（第 3 条）。
   - 加流水线后再跑请注意：这条的 `LD R3,[R1]` 距 `LDI R1` 正好 k=3，会连带依赖第 1 步的下降沿写口。那时请改跑第 3 条——同样的测试，多一条填充避开 k=3。
5. 两个读口接对字段（OUT）+ LDI 立即数通路（§8 第 4 步；§3.2 / §3.4）：
   - `LDI R1,9; ADD R1,R1,R1; OUT R1` → 应显示 18。若显示 0 → A 口没接 `[11:8]`（`OUT` 的源在 A 口）；若显示 9 → A 前递 mux 选错了源（选到 `MEM/WB`，取到的是上一条 `LDI` 的旧值，优先级反了）。
   - `LDI R5,0xC0; OUT R5` → 应显示 0xC0。若显示 0 或别的值 → 立即数没走 B 侧：检查 `BSrc` 是否接在 `ALU.B` 的 mux 上、`LDI` 的 `ALUop` 是不是 `PASS.B`（1000）。若把它接成"立即数进 A、`ALUop` 给 `PASS.A`"，`LDI R5,0xC0` 的 `[11:8]` = 0，写回或送出的就是 R0 的值。
6. load-use（§8 第 7 步；见 §5.2 ①）：跑 `examples/square_lookup.asm`，正解 OUT = `9`；漏插气泡则 `0x00`——13 的 `LD` 紧跟 14 的 `OUT`，而 `OUT` 的源在 A 口，`MEM/WB` 前递赶不上这一拍。这是 load-use 的首选判据（`hazard_k3.asm` 的 `LDA`→`OUT` 也考这一项，但那个 `0x00` 与 k=3 没修好同值，两种成因要一起查，见第 8 条）。最小复现是任何 `LD Rd,[Rs]` 紧跟一条读 `Rd` 的指令。
7. 分支（§8 第 7 步）：跑 `sum1to10`，观察循环次数与最终 OUT=55。
8. 间隔 3 条的 RAW（§8 第 1 / 6 / 7 步；见 §4.1）：跑 `examples/hazard_k3.asm`
   ```
           LDI R5, 0
           STA R5, 0x10     ; 先把 RAM[0x10] 清 0，判据不受 RAM 初值影响
           LDI R1, 0x10     ; 写 Rd 的那条
           LDI R3, 0        ; 填充，把 ST 与 LDI R1 拉开到正好 k=3
           LDI R2, 0xFF
           ST  R2, [R1]     ; <- 用 R1，相隔 k=3
           LDA R4, 0x10     ; 绝对地址读回，不依赖 R1
           OUT R4
           HLT
   ```
   应显示 `0xFF`；若显示 `0x00`，说明 `ST` 读到的 R1 是旧值 0、写进了 `RAM[0]`——寄存器堆写口用了上升沿（见 §2.1），且没补 WB→ID 前递。
9. 分支的源由前一条产生（§8 第 7 步；见 §5.2 ②）：跑 `examples/hazard_branch.asm`
   ```
           LDI R1, 0x10
           LDI R2, 5
           MOV R3, R2        ; R3 = 5（紧邻 BZ）
           BZ  R3, wrong     ; R3≠0，应【不】跳
           OUT R3            ; ← 应显示 5
           HLT
   wrong:  OUT R1            ; 误跳时显示 0x10
           HLT
   ```
   应显示 5；若显示 `0x10`，说明 `BZ` 在 ID 判零时读到了旧的 `R3`（=0）而误判跳转——停顿条件漏了"写 Rd 的那条正在 EX"这一种（`ID_EX.MemRead` 只挡 load）。

   这条三项全考：

   | 去掉哪项修复 | 输出 |
   |---|---|
   | §5.2 ② 分支停顿 | `0x10` |
   | §5.1 的 `EX/MEM` 那一路 ID 前递 | `0x10` |
   | §4.1 寄存器堆下降沿写口（改回上升沿） | `0x00` |

   第三项很反直觉：这条程序静态数不出 k=3，但为 03 插的那 1 拍停顿把 04 的 `OUT R3` 从静态 k=2 推成了流水线 k=3（`MOV R3` 在 WB 的那一拍，`OUT R3` 正好在 ID 读口，只能靠下降沿写口拿到新值）。所以它是一条程序同时验三项，而不是只验分支——这也是它比 `hazard_k3.asm` 更适合当总验收的原因。副作用是：搭第 7 步时它挂了，先别断定是 Hazard Unit 的错，三处都要查。
10. 进位 / 借位（§8 第 8 步）：跑 `add16`（OUT 依次 `0x00`、`0x01`，加法进位）与 `sub16`（OUT 依次 `0xFF`、`0x01`，借位时 C=0），验 C 标志的写入与回读时序。
    这两条刻意排布成无 k=3、无 load-use、无分支（每条 `LDI` 后面都标了它到读 Rd 的那条的距离：全部落在 k=1 / k=2 / k≥4）。只需两个前递 mux 就能跑对，不依赖 §4.1 的下降沿写口——所以它们若出错，可以先排除 §4.1 / §5 那几项冒险，直接查 C 逻辑与前递 mux。这正是拿它们当判据的价值所在（k=3 请用第 8 条的 `hazard_k3.asm`）。
11. 分支源相隔 2 条（k=2，不停顿）（§8 第 7 步；见 §5.1）：跑 `examples/hazard_k2branch.asm`，完整说明在它的文件头。注意 `hazard_branch.asm` 是 k=1（要停），不是本条。下面这段是那个文件的指令部分，两条填充各管一件事：
    ```
            LDI R1, 0x10
            LDI R2, 5
            MOV R3, R2         ; R3 = 5
            MOV R4, R2         ; 填充①：把写 R3 的那条推到 i-2，让 BZ 走 k=2；rd=4，不触发停顿
            BZ  R3, wrong      ; R3=5≠0，应【不】跳
            LDI R5, 0          ; 填充②：把 R3 与 OUT 的距离推到 k≥4，避开 k=3
            OUT R3             ; ← 应显示 5
            HLT
    wrong:  OUT R1             ; 误跳时显示 0x10
            HLT
    ```
    应显示 5；若显示 `0x10`，说明分支操作数的 mux 只接了 `MEM/WB`、没接 `EX/MEM`。这一刻 `EX/MEM` 里装的是 i-2（正是 `MOV R3,R2`），`MEM/WB` 里是 i-3（`LDI R2`，rd=2≠3），单靠 `MEM/WB` 一路够不着 R3，于是读到旧的 R3=0 而误判"该跳"。
    本条与第 9 条的区别：这条不插停顿（写 Rd 的那条是 i-2，`ID_EX` 里是 `MOV R4,R2`），所以它只考 `EX/MEM` 那一路前递，考不到停顿逻辑。
    填充②不能省：少了它，`OUT R3` 与 `MOV R3,R2` 正好相隔 k=3，本条会连带依赖 §4.1 的下降沿写口；写口坏掉时它输出 `0x00`，而这里只声明了 5 / `0x10` 两个值，搭建者会把这第三种结果误记到前递头上。
12. 分支与停顿撞在同一拍（§8 第 7 步；见 §5.1）：跑下面这段，应显示 `0x07`。
    ```
            LDI R3, 9         ; 预置一个非 0 的旧值——停顿拍上读到的就是它
            LDI R1, 0x10
            LDI R2, 7
            MOV R3, R2        ; R3 = 7（紧邻 BNZ，k=1 → 本拍要停顿）
            BNZ R3, tgt       ; 停顿拍上旧 R3=9≠0 → 误判"该跳" → flush 掉自己
            OUT R1            ; ← 出错时显示 0x10
            HLT
    tgt:    OUT R3            ; ← 应显示 7
            HLT
    ```
    若显示 `0x10`，说明停顿拍上 `branch_taken` 没被 `!stall` 封住：那一刻读到的是 00 行预置的旧 R3=9，看着"该跳"，于是 flush 掉了正在停顿的 `BNZ` 自己；而 `PCWrite=0` 又让 PC 没跳——这条分支就凭空消失了，永远等不到前递过来的新值。修法见 §6 表的 `!stall`。

    00 行的 `LDI R3, 9` 不能省：这个 bug 只在旧值与新值判出同一个"跳"时才看得见（完整条件见 §5.1）。旧值若为 0，`BNZ` 在停顿拍上判"不跳"、`branch_taken=0`、根本不产生 flush，下一拍它就用前递来的新值重判，结果完全正确——bug 一点痕迹都不留。所以本条刻意让旧值 9 与新值 7 都判"跳"，唯一的区别才是那次 flush 有没有发生。

    第 9 条的 `hazard_branch` 查不出这个错：它的旧 R3=0 确实让 `BZ` 判了"该跳"、也确实把 `BZ` 冲掉了，但它前递后的新值是 5、判"不跳"——误 flush 之后顺落的 `OUT R3` 恰好就是正解路径，输出仍是 5。
13. 分支源来自 load（§8 第 7 步；见 §5.2 ③）：跑 `examples/hazard_loadbranch.asm`，应显示 `0x05`，完整说明在它的文件头。下面这段是那个文件的指令部分。
    ```
            LDI R1, 0x20
            LDI R2, 5
            LDI R4, 0          ; 填充：把 R1 与 LD 的距离推到 k≥4，避开 k=3
            STA R2, 0x20
            LD  R3, [R1]       ; R3 = 5
            BZ  R3, bad        ; k=1 的 load→分支 → 要停 2 拍
            OUT R3
            HLT
    bad:    OUT R1             ; 出错时显示 0x20
            HLT
    ```
    若显示 `0x20`，说明 load→分支只停了 1 拍。停 1 拍后 load 才刚进 MEM——`EX/MEM` 里只有地址、没有数据——而 `ID_EX` 已换成气泡（`RegWrite=0`），原来的停顿条件自动失效，`BZ` 就拿着旧 R3=0 判定"该跳"。修法见 §5.2 ③（判据是"源还被关在在飞的 load 里"，k=1 停 2 拍、k=2 停 1 拍、k=3 不停）。
    那条填充不能省：没有它，`LDI R1` 与 `LD R3,[R1]` 正好相隔 k=3，本条会连带依赖 §4.1 的下降沿写口——写口坏掉时 `LD` 读到的 R1 是旧值 0，转而去读 `RAM[0]`（初值 0）、载入 R3=0，`BZ` 判"该跳"走进 `bad`，同样显示 `0x20`，与"只停 1 拍"的症状一字不差。两个故障给同一个值，这条调试项就废了。
14. 误停（多插气泡）（§8 第 7 步；见 §5.2）：跑
    ```
            LD  R0, [R2]      ; 写 R0、读 R2
            LDI R1, 0x50      ; 不读任何寄存器；它的 [11:8] 按约定编 0
    ```
    单步观察：这里会多停 1 拍（`LDI` 的 `[11:8]`=0 命中了 `dep` 里的 `ID_EX.rd`=R0），但结果完全正确。同型的另一侧是 `[7:4]`：`LD R3,[R2]` 紧跟 `LDI R1,0x30`（后者的 `[7:4]` = 3）。
    这是设计上接受的代价，不是 bug——不要为了消除它给停顿逻辑加指令类型特判。理由见 §5.2 的误停无害。
15. 未用 mux 输入一律接 Constant 0，勿悬空（通用）。

第 11-13 条是同一类错误：都属于"分支在 ID 取值"特有的时序问题。第 11、13 条的错误恰好被别的通路补上，原来的 8 个程序都测不到，现在各有一个专门的示例文件；第 12 条例外——`fib` / `sum1to10` / `array_sum` 的循环每轮都踩它（错值与正解都判"跳"，正是 §5.1 的可见条件），出错时分别表现为"只输出一次 `1`"、`0x0A`、`0x05`（见 `README.md` 判据表），本条的 `0x10` 只是最小复现的那一个。搭到第 7 步时请把三条都跑一遍。
